## 2. 고령자 읽기 연구

### 2-1. 미국 NIA(국립노화연구소)·NLM(국립의학도서관) 「Making Your Web Site Senior Friendly: A Checklist」(2001) — A등급, 원문 전체 확인

출처: nia.nih.gov / nlm.nih.gov 공동 발행, PDF 사본 확인(huzurevleri.org.tr 미러, arizona.edu 원본 리포지터리도 검색 결과에 존재)

| 항목 | 원문 인용 | 우리 적용값 |
|---|---|---|
| 서체 | "Use a sans serif typeface, such as Helvetica, that is not condensed. Avoid the use of serif, novelty, and display typefaces." | 고딕(산세리프) 계열, 장평 좁힌 폰트 금지 |
| 글자 크기 | "Use 12 point or 14 point type size for body text." | 본문 최소 12pt, 가능하면 14pt(화면 기준으로는 모바일 앱 상대 단위로 환산 필요 — 이 수치는 인쇄물/2001년 화면 해상도 기준, **환산값은 운영자확인필요**) |
| 굵기 | "Use medium or bold face type." | 본문에 얇은(light) 폰트 쓰지 않는다 |
| 대소문자 | "Present body text in upper and lowercase letters. Use all capital letters and italics in headlines only." | 본문 전체 대문자·이탤릭 금지(한글은 해당 없음, 다만 "전체 강조체" 금지로 치환 적용 가능) |
| 줄간격 | "Double space all body text." | 줄간격을 넉넉히(2배 수준 지향). 정확한 배수(1.5배 vs 2배)는 웹 환경 재해석 필요 — **운영자확인필요** |
| 정렬 | "Left justified text is optimal for older adults." | 양쪽정렬(justify) 금지, 왼쪽정렬 고정 |
| 색상 | "Avoid yellow and blue and green in close proximity... Ensure that text and graphics are understandable when viewed on a black and white monitor." | 노랑·파랑·초록의 근접 배색 피함, 명도 대비만으로도 구분되게 |
| 배경 | "Use dark type or graphics against a light background, or white lettering on a black or dark-colored background." | 밝은 배경+어두운 글자(또는 반대), 무늬 배경 금지 |
| 문체(태도) | "Present information in a clear and familiar way to reduce the number of inferences that must be made. Use positive statements." | 추론 시켜야 하는 표현 금지, **긍정문 우선**(부정문보다) |
| 어투(능동/수동) | "Use the active voice." | 능동태 우선 |
| 어휘 | "Write the text in simple language. Provide an online glossary of technical terms." | 쉬운 말 우선, 전문용어는 별도 설명 |
| 구조 | "Organize the content in a standard format. Break lengthy documents into short sections." | 긴 글은 짧은 섹션으로 쪼갠다, 매 페이지 구조 통일 |
| 내비게이션 | "The organization of the web site should be simple and straightforward. Use explicit step-by-step navigation procedures whenever possible to ensure that people understand what follows next." | 순서형(1-2-3 단계) 안내가 있으면 사람들이 다음에 뭘 할지 안다 — **"보자마자 할 일" 구조의 직접 근거** |
| 버튼 | "Incorporate text with the icon if possible, and use large buttons that do not require precise mouse movements for activation." | 아이콘만 쓰지 말고 글자를 같이, 버튼은 크게(터치 오차 감안) |
| 메뉴 | "Use pull down menus sparingly." | 드롭다운(펼침 목록) 최소화 |
| 도움 | "Offer a telephone number for those who would prefer to talk to a person." | 전화번호를 같이 노출 — 사장님 콘텐츠에 그대로 적용 가능 |

이 문서는 2001년 발행으로 오래됐지만, **현재도 W3C WAI Older Users Online·NN/g 등이 반복 인용하는 기초 문헌**이다. 다만 "double space", "12~14pt"는 인쇄/PC 브라우저 시대 수치이므로 모바일 반응형 환경 그대로 적용은 무리가 있다 — **운영자확인필요(디자이너 검토)**.

### 2-2. Nielsen Norman Group(NN/g) — B등급(스니펫), 일부는 검색 결과 인용문 형태로 확인

- "Sites that target seniors should use at least 12-point fonts as the default. Additionally, all sites... should let users increase text size as desired." (NN/g, "Let Users Control Font Size" / "Usability for Senior Citizens" 계열 기사, 정확한 게재 연도 미확인)
- "you should avoid tightly clustered links by using white space to separate links, which decreases erroneous clicks" (요지, 원문 정확한 워딩 미대조)
- 정량 성능 데이터(별도 확인, NN/g "Usability for Senior Citizens: Improved, But Still Lacking", nngroup.com): 65세 이상 사용자는 21~55세 사용자보다 과제 수행 시간이 43% 더 걸림(7:49 vs 5:28), 성공률 55.3% vs 74.5%, 오류 2.4회 vs 1.1회. → **"쉬운 글이 실제로 시간을 아껴준다"는 정량 근거로 인용 가능**
- 87개 가이드라인을 담은 리포트 "UX Design for Seniors, 3rd Edition"가 존재(유료 리포트, 원문 미대조) — 구매 전에는 세부 항목 인용 불가, **미확인**

**한국어로 옮길 수 있는 것(판단, 출처는 위 표 근거):**
- 문장 15~20단어 상당 → 한국어는 어절 기준으로 환산 필요. 통상 번역 관행상 영어 20단어 ≈ 한국어 1문장 40~50자 내외로 보는 경우가 많으나, **이 환산 자체는 학술적으로 검증된 공식 수치가 아님 — 미확인, 잠정 적용값으로만 사용**

| 국립국어원 순화어(랜딩페이지·키워드·트래픽·콘텐츠·플랫폼 등) | 이번 조사에서 다듬은말 사전(korean.go.kr 새말모임/다듬은말) 검색 못함(한도 소진) | 미확인 | **운영자확인필요 — 다음 조사에서 korean.go.kr 다듬은말 게시판을 직접 뒤져야 함.** 이번엔 확보 못함 |

| 첫 화면 | 스크롤 없이 "결론(할 일)"이 먼저 보이게 | GOV.UK front-loading(B, 스니펫) + NIA step-by-step(A) | 확인됨(원칙) — 정확한 화면 높이·글자수는 미확인 |

| 목록 | 목록 앞에 리드 문장 1개, 항목은 마침표 없이 1문장 이내, 번호 목록은 순서(단계)가 있을 때만 | B(GOV.UK, 스니펫) | 운영자확인필요(원문 재확인 권장) |

## 확인됨 / 미확인 / 운영자확인필요 (종합)

**확인됨** (원문 또는 신뢰 가능한 근거로 뒷받침)
- NIA/NLM(2001) 체크리스트 전문: 능동태·긍정문·쉬운 말·짧은 섹션·단계형 안내·왼쪽정렬·전화번호 병기·본문 12~14pt·굵기 medium 이상·양쪽정렬 금지
- Federal Plain Language Guidelines: 문장 평균 15~20단어, 한 문단 한 주제
- GOV.UK(스니펫 수준이지만 정부 공식 지침으로 신뢰도 있음): 목록 앞 리드 문장, 목록 항목 마침표 없음·1문장 이내, front-loading(중요한 것 먼저), 9세 읽기 연령 목표
- NN/g 정량 데이터: 고령자는 젊은 사용자보다 과제 시간 43% 더 걸림, 성공률 낮고 오류율 높음 → "쉬운 글"의 효과 근거로 사용 가능

**미확인** (이번 조사에서 원문 대조 못함, 추측 없이 빈칸으로 둠)
- 한국 공식 지침(국립국어원 2022 「쉬운 공문서 쓰기 길잡이」)의 정확한 문장 길이·문단 줄 수 수치
- KRDS·서울시 「쉬운 우리말」·국민연금/건보공단 안내문 작성 기준
- 국내 고령자 웹 가독성 논문(글자 크기·줄 간격·명조/고딕 비교 실험)
- W3C WAI Older Users Online 원문, Microsoft Inclusive Design 원문
- やさしい日本語 규칙 원문
- 국립국어원 순화어 목록(랜딩페이지·키워드·트래픽·콘텐츠·플랫폼 등)
- 해요체 vs 합쇼체 중 고령자에게 더 적합한 쪽에 대한 학술적 근거
- 한글 기준 줄 길이(가로 글자 수)·모바일 한 줄 글자 수·문단 줄 수 정량 기준
- 표 vs 목록 선택 기준, 숫자 표기(한글 수사 vs 아라비아) 정량 근거
- BLUF·역피라미드의 1차 출처, 체크리스트형 안내 효과 연구

**운영자확인필요**
- 이번 조사가 세션 WebSearch 한도(200회) 소진 상태에서 시작되어 5회만 쓰고 막혔다. **다음 세션에서 한도를 늘리거나 새 세션으로 국립국어원 2022 지침·KRDS·국내 논문·순화어 목록을 마저 조사할지** 결정 필요
- NIA 수치(12~14pt, double space, 왼쪽정렬)는 2001년 PC/인쇄 기준이다. **모바일 반응형 환경에 그대로 적용할지, 디자이너가 재해석할지** 결정 필요
- 「우리 글 규칙 초안」 표의 잠정값(문단 2~4줄, 강조 문단당 1곳, 숫자는 아라비아)은 공식 근거가 없는 실무 관행값이다. **이대로 확정해 발행 기준에 넣을지, 근거 있는 항목만 넣을지** 설계자 판단 필요
- 말투(해요체/합쇼체/"~하세요")는 이미 BRAND.md에 톤 규칙이 있을 가능성이 높다. **이 조사 결과와 BRAND.md 중 무엇을 우선할지** 확인 필요
