# 레퍼런스 종합 분석과 개선 기획 (2026-09-21)

운영자 지시: "우리와 유사한 교육목적 홈페이지들 레퍼런스들 조사해서 … 실제로 사용자가 많고 평이 좋은 리뷰가 많은 그런 홈페이지 위주로들로 3개정도만 선정해서 진짜 모든 코드를 훑는다 싶을정도로 자세히 조사해서 어떤식으로 구조가 짜여져있고 어떤 정보를 사용자에게 주고 강점은 뭐고 유입된 사용자들이 뭘 목적으로하고 … 그 장점들을 종합해서 우리 홈페이지에 적용하면 어떤식으로 개선 및 디벨롭이 가능한지까지 분석 및 기획해봐"

개별 조사 문서(실측값·출처 URL 전부 수록): `govuk.md` · `investopedia.md` · `tossfeed.md`
이 문서는 세 건을 합쳐 **우리 사이트와 견주고, 무엇을 어떤 순서로 바꿀지**를 정한다. 확인하지 못한 것은 「미확인」으로 남긴다.

## 2. 세 곳이 공통으로 하는 것 (= 검증된 원칙)

| 원칙 | GOV.UK | Investopedia | 토스피드 | 우리 현재 |
|---|---|---|---|---|
| **첫 문장이 답이다** | 첫 문단에 정의·결론("Self Assessment is a system HMRC uses to…") | 첫 문장이 곧 정의이자 meta description | 표지+제목+필진 뒤 바로 본문 | `.lead` 뒤 「한 줄 답부터.」 인용 박스 있음 ✔ (글마다 있는지는 미확인) |
| **본문 폭을 좁게** | 컨테이너 960 안 본문 칼럼 ≈600~640px | 본문 600px 고정 | 700px | 720px(2단일 때)·680px ✔ |
| **글자 크고 줄 간격 넉넉** | 19px / 1.32 | 18px / 1.5 | 17px / 1.6 | **18px / 1.78** — 셋보다 넉넉. 50대 독자에게 맞음 ✔ |
| **소제목이 곧 목차** | 서술형·동사 시작, 질문형 금지 | 「What Is X?」「How Can I…」 Q&A 형 | Q1~Q5 번호·질문형 | 질문형 h2 다수(「1. 하루 사이 변동인가요?」) — Investopedia·토스 방식과 같음 |
| **관련 글은 끝에, 제목+한 줄** | related-navigation | Related Terms(제목+요약+more) | 추천 콘텐츠 카드 | 「다음」 박스 + 이전·다음 ✔, 관련 용어 목록은 없음 |
| **날짜를 밝힌다** | JSON-LD datePublished/Modified | 「Updated July 19, 2022」+ 정정 정책 | 「2025.07.09. 기준으로 작성」 고지문 | 발행·수정일 ✔, **원문 확인일**은 인용 박스마다 ✔. 글 끝 기준일 고지문은 없음 |
| **구조화 데이터** | Article·FAQPage·BreadcrumbList | Article 하나에 breadcrumb·저자·출처·영상 통합 | Organization 만(따라 하지 말 것) | Article + BreadcrumbList ✔. FAQPage 없음 |
| **이미지는 아껴서** | 허브·본문 0, 홈 4 | 용어마다 **직접 만든 도표** 1 | 표지 1 + 글 성격 따라 0~7 | 첫 화면 타일 9, 개념 글 「그림 1」 시작(1편) |

**결론:** 세 곳 다 「첫 문장=답, 좁은 본문, 큰 글자, 소제목=목차, 끝에 관련 글, 날짜 명시」를 지킨다. 우리는 이 여섯 가지를 이미 대부분 하고 있고, 빠진 것은 **핵심 요약 박스·관련 용어·기준일 고지·FAQPage·편집 원칙 페이지** 다.

## 3. 세 곳이 각자 잘하는 것과 우리 적용 가능성

### 3-1. GOV.UK — 「절차를 끝내게 한다」

| 강점 | 구체적 방식(실측) | 우리 조건(정적·JS 없음·CSP) | 적용 |
|---|---|---|---|
| 단계별 안내(step-by-step) | `<ol><li>` 단계 → 안에 다시 `<ol><li><a>` 링크 목록. **JS 없으면 전체 펼침이 기본** | 그대로 가능 | 우리 `/setup/<slug>/` 가 이미 같은 구조. 단계 안에 「이 단계에서 할 일 2~3개」 하위 목록을 넣으면 GOV.UK 와 같아짐 |
| 다중 파트 글 목차 | `<nav aria-label="Pages in this guide"><ol>` 별도 페이지 링크, 현재 파트 `aria-current="true"` | 가능 | 우리 코스(`/local/1-…`)의 `step_nav` 에 `aria-current` 추가, 코스 전체 목차를 글 위에 |
| 글쓰기 규칙(1차 출처 확인) | 문단 ≤5문장, 25단어 넘으면 쪼개기, 능동태, 의무 강도를 must/need/can 으로 구분, 질문형 헤딩 금지, 각주 금지 | 문장 규칙이라 코드 무관 | **한국어판 규칙**으로 옮겨 `docs/규칙/글쓰기.md` 에 넣고 `check.py` 경고로 잰다(아래 5절) |
| 발행 기관 명시 | `<meta name="govuk:primary-publishing-organisation">` | 가능 | 우리는 인용 박스에 기관명 ✔. 글 머리에 「근거 문서: 네이버 고객센터 3건, 공정위 1건」처럼 **근거 기관 줄** 추가 검토 |
| 텍스트 중심, 이미지 0 | 허브·검색·본문 이미지 없음 | 가능 | 허브·목록 페이지는 이미지 없이 유지(현재도 그러함). 삽화는 개념 글에만 |
| 안 되는 것 | 서버 검색 폼, 「Is this page useful?」 POST 폼, 질문 분기(smart answer) | 불가 | 검색은 현재 외부 검색 링크 방식 유지. 피드백은 메일 링크로만. 분기는 「1분 자가진단」처럼 정적 표로 |

### 3-2. Investopedia — 「용어 뜻을 찾으러 온 사람을 붙잡는다」

| 강점 | 구체적 방식(실측) | 우리 조건 | 적용 |
|---|---|---|---|
| 정의 한 문장이 맨 위 | h2 「What Is X?」 → 정의 1문장 → 본문 | 가능 | 용어 페이지 각 항목이 이미 「한 줄 정의 + 자세한 글 링크」 ✔. 설명 글도 첫 문단을 정의로 시작하게 통일 |
| **Key Takeaways 박스** | `<div class="callout"><h3>Key Takeaways</h3><ul>` 서론 직후 | 가능(클래스 CSS) | **「핵심 정리」 박스 3~5줄**을 `.lead` 아래에. 바쁜 독자가 이것만 읽어도 되게. 현재 「한 줄 답부터」 인용 박스를 이 자리로 승격 |
| 3단 바이라인(작성·검수·팩트체크) | 모든 글 상단, 이름에 툴팁 | 툴팁은 JS 라 불가. **실존 검수진이 없으면 흉내내면 안 됨(허위 신뢰 신호)** | 우리는 사람 대신 **「원문 대조 2026-09-19, AI 작성, 운영자 검수」** 처럼 사실 그대로 적는 줄 하나. 문구는 운영자 결정 |
| 편집 원칙 페이지 | Empowering/Unbiased/Accurate/Inclusive 4원칙, 정정 정책, 「1차 출처만 쓴다」 고정 문구를 매 글 반복 | 가능 | **「이 사이트가 글을 쓰는 방법」 페이지**(원칙·출처 규칙·정정 방법·AI 관여 범위)를 만들고 모든 글 출처 박스에서 링크. 이미 `about` 이 있으면 거기에 절 추가 |
| 접이식 출처 | `<div class="article-sources">` + `<ol>` | 접기는 `<details>` 로 JS 없이 가능 | 우리는 인용을 본문 안에 두므로 접을 필요 없음. 대신 글 끝에 **「이 글의 근거 문서 N건」 목록**(제목·기관·확인일)을 자동 생성 |
| Related Terms | 제목 + 1~2문장 + more | 가능 | 설명 글 끝에 **「이 글의 용어」** 3~5개(정의 한 줄 + 용어 페이지 링크) 자동 삽입 |
| Q&A 소제목으로 「함께 묻는 질문」 흡수 | 본문 후반 「How Can I…」「Who Benefits…」 | 가능 | 글 끝 「막히면」 절이 이미 이 역할. **FAQPage JSON-LD** 를 「막히면」 절에서 자동 생성 |
| 안 되는 것 | 광고 51개, 툴팁·TOC 접기 버튼·뉴스레터 폼 | 불가·불필요 | 반면교사: 본문 흐름을 끊는 삽입물 금지 |

### 3-3. 토스피드 — 「한국어로 쉽게, 끝까지 읽히게」

| 강점 | 구체적 방식(실측) | 우리 조건 | 적용 |
|---|---|---|---|
| 본문 17px/1.6, 폭 700, 문단 margin 24px | Emotion CSS(인라인) | 값만 참고 | 우리 18px/1.78/720 이 더 넉넉 — 유지 |
| 기준일 고지문 | 글 끝 「해당 콘텐츠는 2025.07.09. 기준으로 작성되었습니다」 + 면책 | 가능 | **「이 글은 2026-09-19 에 확인한 원문 기준이에요. 규정이 바뀌면 수정일을 갱신해요.」** 를 `cite` 박스 위에 자동 삽입. 문구 운영자 확인 |
| 4갈래 분류(카테고리·시리즈·에디션·작가) | 허브 4종 | 가능 | 우리는 플랫폼·채널·세팅·용어 4갈래 ✔. 「시리즈」= 우리 코스. 부족한 건 **「특집(에디션)」** — 예: 「대행사 전화 받았을 때 전부」 같은 주제 묶음. 큐에 후보로만 |
| 전문용어 뒤 원어 병기 | 「스테이블코인(Stablecoin)」 | 가능 | 우리 용어에 영문 병기는 불필요(네이버·구글 용어는 한글). 대신 **화면에 보이는 정확한 메뉴명**을 「」로 병기(이미 함) |
| 짧은 한국어 alt | 「스테이블코인에 하이라이트된 이미지」 | 가능 | 타일·삽화 alt 를 같은 식으로 점검 |
| 안 되는 것 | 인라인 style·CSS-in-JS, Notion id 노출, Article 스키마 없음, JS 검색 | 불가·따르지 말 것 | — |

## 4. 유입 사용자의 목적과 첫 화면이 주는 것

| 사이트 | 들어오는 사람의 목적 | 첫 화면·첫 문장이 주는 것 | 우리 |
|---|---|---|---|
| GOV.UK | 「지금 이 절차를 끝내야 한다」(검색 유입 2/3) | 검색창 중앙 + 주제 카드. 글은 절차 첫 단계로 바로 | 「따라만 하면 되는 세팅」(플랫폼별) ✔ — GOV.UK 와 같은 방향 |
| Investopedia | 「이 용어가 무슨 뜻인가」(검색 유입) | 정의 한 문장, Key Takeaways | 용어 페이지 ✔. 설명 글에 **핵심 정리 박스** 없음 → 추가 |
| 토스피드 | 「금융이 궁금하다」(앱 유입·재방문) | 표지 그림 + 제목 + 필진 | 우리 독자는 재방문보다 검색·AI 인용 유입이 목표(실험 목표 문서) → 토스식 표지보다 **GOV.UK·Investopedia 식 「답 먼저」** 가 맞음 |

우리 독자(사장님)는 세 유형이 다 온다: ① 「플레이스 등록 어떻게」(절차) ② 「어뷰징이 뭐야」(용어) ③ 「대행사 전화 받았는데」(판단). ①은 세팅 묶음, ②는 용어 페이지가 받고, **③ 판단형 글이 핵심 요약 박스가 없어 가장 약하다.**

## 5. 개선·디벨롭 기획 (우선순위)

### 1단계 — build.py 한 번 고치면 전 페이지 반영 (코드 작업, 이번 주)

| # | 할 일 | 근거 | 방법 |
|---|---|---|---|
| R1 | **「핵심 정리」 박스** 를 `.lead` 아래 자동 배치 | Investopedia Key Takeaways | 글 안 첫 `blockquote`(「한 줄 답부터」)와 `.note.todo`(바로 할 일)를 묶어 `<aside class="keys">` 로. 없는 글은 keys.py 의 결론 문장으로 생성 |
| R2 | **「이 글의 근거 문서 N건」** 목록을 글 끝 자동 생성 | Investopedia Article Sources, GOV.UK 기관 명시 | 본문 인용 박스의 문서명·기관·확인일을 모아 `<section class="sources-list">` |
| R3 | **기준일 고지문** 자동 삽입 | 토스피드 | 인용 박스의 확인일 중 최신 값으로 「2026-09-19 확인한 원문 기준」 |
| R4 | **FAQPage JSON-LD** 를 「막히면」 절에서 생성 | GOV.UK FAQPage, Investopedia Q&A | h2 「막히면」 아래 h3/p 쌍을 Question/Answer 로. 3개 이상일 때만 |
| R5 | **「이 글의 용어」** 3~5개 자동 삽입 | Investopedia Related Terms | 본문에 나온 용어 중 `terms/*` 에 있는 것을 정의 한 줄과 함께 |
| R6 | 코스 목차에 `aria-current`, 세팅 단계 안에 「이 단계에서 할 일」 하위 목록 | GOV.UK step-nav | `step_nav`·`setup_steps_html` 수정 |
| R7 | 검사기에 **글쓰기 경고** 추가: 문단 6문장 이상, 한 문장 70자 이상, 각주 | GOV.UK 5문장·25단어 규칙의 한국어판 | `check.py` 경고(오류 아님). 현재 rank-drop 평균 문장 52자·77문장 |

### 2단계 — 글 단위 (조사·잡무는 서치-소넷, 판단은 설계자)

| # | 할 일 | 근거 |
|---|---|---|
| R8 | 설명 글 첫 문단을 **정의·결론 문장**으로 시작하는지 전수 점검, 아니면 고침 | 세 곳 공통 |
| R9 | h2 를 「서술형·동사 시작」 또는 「질문형」 한 가지로 통일(현재 혼용). 권장: 판단형 글은 질문형, 절차 글은 동사형 | GOV.UK(질문 금지) vs Investopedia(질문형) — 글 유형별로 나눔 |
| R10 | 개념 글마다 **직접 만든 도표 1장**(SVG 속성 방식) | Investopedia 용어마다 도표 1 | rank-drop 「그림 1」 방식 확장. 허브·목록은 이미지 0 유지 |
| R11 | alt 문구를 「무엇이 그려진 그림」 한국어 한 줄로 통일 | 토스피드 |

### 3단계 — 운영자 결정이 필요한 것 (⚠ 진행 전 확인)
