## 2. 규칙 파일이 지켜야 할 모양

- 파일 하나 = 일 하나. **한 화면(120줄 안)** — 넘치면 쪼개고 이 표에 줄을 더한다
- 맨 위에 「언제 읽나」, 안에 「어디에 무엇(경로)」·「지켜야 할 것」·「도구」·「고칠 때」
- 다른 파일 내용을 베끼지 않고 **경로로 가리킨다**(같은 규칙이 두 곳이면 한쪽이 낡는다). 말투 규칙은 ko-tone 한 곳, 수치는 `spec.json`·`tone.json` 한 곳
- 새 규칙: 해당 파일에 넣고 → 이 표에 경로가 없으면 한 줄 추가 → `site/docs/설계기준.md` 에 D 번호로 결정 기록 → 작업일지에 「규칙 추가」 한 줄
- 규칙끼리 부딪히면: 보안 > 근거 > 글쓰기 > 레이아웃 순. 운영자 지시가 규칙과 다르면 한 문장으로 걱정을 말하고, 다시 말하면 지시대로 하고 D 번호로 남긴다
- 도구(스크립트)는 **레포 안** `site/_build/` 에. 스크래치패드는 세션이 끝나면 사라진다
