> 첫 실행 기록: `marketing-doctor/조사/유튜브-2026-10-12/README.md`(대조표·반영 안 한 것). 설계: `site/docs/설계기준.md` D110·D111.

## 순서

1. **채널 확정** — 이름이 같은 채널이 여럿이면(예: 「이과장」 콩트 채널 vs 마케팅쉐어_이과장) 구독자·영상 주제로 고르고 보고에 적는다. 틀리면 운영자가 고쳐 준다.
2. **목록·조회수** — PlayMCP 유튜브 검색은 하루 한도가 자주 찬다. 업로드 재생목록(`UU` + 채널 ID 뒤 22자)을 `get_playlist_items` 로, 날짜·조회수는 `python -m yt_dlp --skip-download --print "%(id)s|%(upload_date)s|%(view_count)s|%(duration)s|%(title)s"` 로 받는다.
3. **고르기** — 운영자가 연도를 말하면 그 연도만. 플랫폼(네이버·SNS·당근·메타 …)별 조회수 상위. 매출 사례 위주 영상·유료 강의 홍보 영상은 뺀다.
4. **자막 정독** — 조사 담당(서치-소넷)을 플랫폼 묶음별로 나눠 동시에. 자막 전체를 처음부터 끝까지 읽는다.
   - `yt-dlp --write-auto-subs --sub-langs "ko.*" --skip-download` 가 「Sign in to confirm you're not a bot」·429 로 막히면 `--extractor-args "youtube:player_client=android"`. 셋이 동시에 받으면 더 잘 막힌다.
   - `marketing-doctor/엔진/영상분석/vtt2txt.py` 출력은 콘솔 `>` 로 받지 말고 파이썬에서 UTF-8 로 쓴다(cp949 로 깨짐).
5. **대조** — 영상 주장마다 창고 공식 문서와 「일치 / 어긋남 / 창고에 없음」. 어긋나면 양쪽을 다 적고, 판단은 설계자가 한다. 창고에 없으면 원문을 받는다(근거.md).
6. **반영** — 아래 「사이트에 쓰는 법」.
7. **기록** — 저장소에는 설계자가 쓴 요약 README 한 장(대조표·반영 안 한 것과 이유)만. 영상별 노트와 자막은 저작권 때문에 커밋하지 않는 `참고/유튜브분석-<연월>/` 에 둔다.

## 사이트에 쓰는 법

| 경우 | 어떻게 |
|---|---|
| 공식 문서로 확인된 주장 | 「영상에서 자주 듣는 말」을 질문 소제목으로 받고, 공식 원문 인용(Q1)으로 답한다. 해당 설명 글에 절을 더하는 쪽이 새 글보다 낫다 |
| 공식 문서와 어긋나는 주장 | 공식 문서를 기준으로 쓰고, 실무자 주장은 아래 상자에 「~라는 실무자도 있어요」로 |
| 공식 근거가 없는 현장 방법(릴스 만드는 순서 등) | 보라색 상자 `<div class="note practice"><b>실무자 노하우</b>…</div>` 에만. 이름표는 **「실무자 노하우」 한 마디** |
| 매출·조회수 성공 사례 숫자 | 쓰지 않는다 |
| 법 쟁점(전화번호 타게팅 등) | 법령 검토 전에는 다루지 않는다 |

- **유튜브 채널 이름·영상 링크는 사이트 어디에도 쓰지 않는다**(상자 안·근거 목록 모두). 근거 목록에는 채널 없이 `<span class="grade">실무</span> 「실무자 노하우」 상자는 현장 실무자의 경험이라 공식 문서로 확인한 내용이 아니에요.` 한 줄.
