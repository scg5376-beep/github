> 운영자(2026-10-06): «그리고 이제 노출을 위한 도메인 블로그 저널을 좀 쓰면 좋을거같은데 이건 히스토리 세션과 세컨페이스 세션 둘다의 경험과 학습로그 현재에 이르기까지의 변화등 한번 정독해서 전략세워봐» → (10-07) «추천대로 진행»
> 전략과 근거(세 레포 실측): `docs/발전/저널_전략.md`. 설계 결정: `site/docs/설계기준.md` D102.

## 어디에 무엇

| 무엇 | 경로 |
|---|---|
| 글 원본 | `site/_src/pages/journal/<영문-주소>.html` (목록은 `journal/index.html` 의 `<!--journal-->`) |
| 예약 발행 | 메타 `"kind": "journal"`, `"published": "YYYY-MM-DD"`. 그날 전에는 빌드하지 않는다(`build.py` read_pages) |
| 자동 실행 | `.github/workflows/pages.yml` 매일 07:05(한국 시각) 빌드·검사·배포 → 새 글 알림 |
| 새 글 알림 | `site/_build/indexnow.py`(네이버 서치어드바이저·api.indexnow.org). 키 파일 `site/<32자>.txt` |
| 첫 화면 띠 | `build.py` home_c_html — 발행된 글이 있을 때만 최신 3편 |
| 미리 보기 | `JOURNAL_TODAY=2026-10-30 python site/_build/build.py` → 확인 뒤 **반드시 날짜 없이 다시 빌드하고 커밋**(미리 본 글이 커밋되면 예약 전에 공개된다) |

## 글 종류 넷 (`"jkind"`)

| jkind | 이름 | 무엇 | 근거 |

| change | 이달의 바뀐 것 | 플랫폼 공지·보도자료로 「이번 달 손댈 것」, 마감 순서 | 공식 원문(근거.md), `/updates/` 항목 |

## 지켜야 할 것

1. **누가 썼는지 밝히지 않는다**(운영자 2026-09-21 «그런걸 밝히지마»). 실측 사례도 「이 사이트」 「다른 사이트 한 곳」으로, AI·작성자·검수자 이야기 없이 숫자·날짜만
2. **실측 사례는 측정값만**(D33 예외, D102). 기분·인상·「저희가 해 보니」 식 경험담은 쓰지 않는다. 재지 않은 칸은 「재지 않음」, 모르면 「미확인」
3. 출처 없는 숫자 0(보안·근거). 기존 글의 숫자를 옮길 때는 그 글의 근거 원문을 footer 에 같이 단다. 인용은 `<q>` 로 창고 원문 글자 그대로(Q1)
4. **주 3편(월·수·금)** 넘게 올리지 않는다. 한날 몰아 예약 금지(역사 레포: 매일 53편 색인 0). 종류는 돌아가며
5. **한 편에 한 가지.** 여러 가지면 연재(1편·2편·3편)로 나눈다. 한 편 400~900자, 그림 3장 이상(날짜 길 `ol.jt`, 막대 `.jb`, 둘 비교 `.jvs`, 화면 모형 `.vx-mock`). 첫 화면에 「바로 할 일」 + 그림 한 장. 결론 먼저(D99·D105)
6. 글마다 관련 길라잡이·설명 글 3~6편 링크(아직 안 잡힌 쪽으로 가는 길, 역사 레포 실측)
7. 같은 글을 다른 곳(네이버 블로그 등)에 붙여 넣지 않는다 — 네이버는 먼저 잡힌 쪽을 원본으로 본다(안경원 레포 조사)
8. 제목 시작어·결말 절 이름이 여러 편에서 같지 않게(정리 절은 예외). 그림은 AI 그림 대신 표·도표
9. 예시 업종은 미용실·식당·카페·학원(보안 3). 광고주·매장·운영자 정보 금지
10. 날짜가 지나면 틀리는 말(마감·요율)은 「이 글은 YYYY년 M월 D일 기준」을 footer 에

## 순서 (한 묶음)

1. `docs/발전/저널_전략.md` 편성표에서 다음 칸 → 근거 원문 확인(창고·기존 글 footer)
2. 글 쓰기 → `JOURNAL_TODAY=<발행일>` 로 빌드·`check.py` 오류 0 → 400폭 캡처 눈 확인
3. 날짜 없이 다시 빌드 → `check.py` → 커밋(배포.md). 그날 아침 자동 실행이 올리고 알린다
4. 발행 다음 주: `docs/발전/신호.md` 에 네이버 색인 쪽수·글별 순위 한 줄

## 연재 (2026-10-11, D105)
> 운영자: «일단 그거보다 한 포스트에 길이 너무길어 하나하나 단계별로 세분화에서 포스팅하면좋을거같아 그리고 포스팅에 정보를 도와주는 이미지가 최대한 많이 들어갔으면 좋겠어» · «저널도 그렇고 거기 방법설명해주는 것들도 너무 한페이지에 정보가많아 그냥 1단계 2단계 이런식으로 사람들이 단계별로 따라갈수있게끔 커리큘럼형식으로 만들어줘»

- 메타에 `"series": "영문-이름"`, `"series_title": "연재 이름"`, `"part": N` 을 넣으면 빌드가 위에 「연재 · 이름 · N / 전체편」 막대, 아래에 「연재 차례」를 붙인다. 아직 안 올라간 편은 링크 없이 「M월 D일(요일) 올라와요」.
- 편마다 앞 편 한 줄 요약으로 시작하고(「1편에서는 ~」), 끝에 다음 편 예고. 마지막 편은 「세 편을 묶으면」으로 정리.
- 연재 편도 주 3편(월·수·금) 안에서 다른 연재와 돌아가며 올린다(한 연재를 연달아 몰지 않는다).
- 막대 폭은 `class="w0"~"w100"`(5 단위). HTML 안 `style="…"` 은 CSP 가 막는다.
- 공유 그림은 `og_pages.py` 가 예약 편까지 미리 만든다(서버 자동 빌드는 그림을 못 만든다).
