## 네이버 수집 요청 순서 (`site/_build/sa.mjs`)

1. `node site/_build/sa.mjs open` → 전용 프로필(edge-sa) Edge 창이 수집 요청 화면으로 열린다. 로그인 화면이면 **운영자에게 로그인을 부탁**한다(비밀번호는 넣지 않는다, 보안.md).
2. `node site/_build/sa.mjs dom` 으로 주소가 `searchadvisor.naver.com/console/site/request/crawl` 인지 확인.
3. 주소 목록 파일(한 줄 한 주소)을 **10건씩** `node site/_build/sa.mjs submit 파일 10`. 한 건마다 약 5초 띄운다(스크립트 기본값).
4. 묶음마다 `dom` 으로 「수집 요청 내역」에 같은 수가 새로 들어갔는지 센다. 결과 문구에 찍히는 「warning」은 화면 아이콘 글자라 실패 뜻이 아니다. 내역이 「데이터가 없습니다」로 비거나 응답이 멈추면 일시 제한으로 보고 그날은 멈춘다(10-09).
5. **하루 20~30건.** 넘치는 것은 `docs/발전/수집요청.md` 에 남은 목록으로 두고 다음 날.

## 무엇을 넣나 (우선순위)

1. 새로 만든 글(색인에 없는 것)
2. 전에 한도 때문에 남겨 둔 목록(`docs/발전/수집요청_남은것_*.txt`)
3. 크게 고친 설명 글·강의 쪽

**넣지 않는 것**: 단계·질문 쪽(noindex, canonical 이 강의·글 쪽) · 공개 전 예약 저널(그날 07:05 자동 공개·알림) · 옮긴 옛 주소 안내 쪽(10-09 실수: 목록에 섞였다).
