# 규칙 · 설명 글 (개념 `/guide/` · 효과 `/why/` · 용어 · 업데이트)

> 설명 글은 「왜·어떻게 돌아가나·무엇이 효과 있었나」를 근거와 함께 쓴다. 따라 하는 절차는 넣지 않는다(→ 방법글.md).

## 어디에 무엇

| 것 | 경로 |
|---|---|
| 글 원본 | `site/_src/pages/guide/*.html` (23편) — 손으로 고친다. 생성기 없음 |
| 어느 문에 속하나 | `site/_build/build.py` `WHY_URLS`(효과 7편) — 나머지 guide/ 는 개념. `page_area()` |
| 용어 | `site/_src/pages/terms/index.html` — `dl.terms`, 한 줄 풀이 + 자세한 글 링크 |
| 업데이트 | `site/_src/pages/updates/index.html` — `dl.updates`, 날짜 내림차순, 근거 글 링크 |
| 인용·사례 원문 | `marketing-doctor/지식/원전/` (근거.md) · 사례집 `marketing-doctor/지식/문체/사례집-*.md` |

## 한 편의 구조 (D32·D34)

1. kicker(게시판 이름은 빌드가 붙임) · h1 · lead(결론을 먼저)
2. 첫 문단: 「사장님」 호칭 + 지금 이 글을 왜 읽는지
3. 소제목은 **독자 질문형**(「리뷰가 매출을 움직이나요?」) — 검사기 H5 가 질문 수 하한을 본다
4. 본문: 결론 → 이유(-거든요·-잖아요) → 예시(미용실·식당·카페) → 번호 항목에는 이유를 붙인다
5. 인용은 `<q>`·`blockquote.official`·「」로, 창고 원문과 **글자 그대로**(Q1). 그림·표·인용은 재작성 때 손대지 않는다
6. 실제 사례 `p.case` 최소 1개(H13 경고). 상호는 업종·지역까지만. 대행사 홍보 글은 사례로 안 쓴다. 편집자 경험담은 쓰지 않는다(D33)
7. 정리 + 다음 글 · 근거 footer(문서 이름·판본·등급 A/B·확인 날짜) · 「다시 확인 YYYY-MM」은 빌드가 계산

## 문장 (자세한 건 ko-tone · 글쓰기.md)

- 문장 평균 40~65자, 상한 110자, 20자 미만 15% 이하, 조각문 0, 문단 5문장까지
- 같은 종결 3연속 금지, 문두 접속사 쪽당 5회, 가능형 5회, 강조 부사 3회
- 해요체 기본에 합쇼체 8~40% 섞음

## 용어·업데이트 쓸 때

- **기존 글에 있는 사실만** 옮긴다. 용어 풀이는 일반 정의 + 그 개념 글 링크. 새 숫자·날짜를 여기서 처음 쓰지 않는다
- 업데이트 한 줄 = 날짜 · 플랫폼 · 무엇이 바뀌었나 · 근거 글 링크. 원문을 못 확인한 변경은 넣지 않고 아래 「여기 없는 변경은 …」 문장으로 남긴다
- 새 항목을 넣을 때 그 근거가 있는 개념 글이 먼저 있어야 한다

## 강조 (D44)

- 빌드가 붙인다: 돈·기한·한도 숫자 형광펜(문단당 1), 문서 제목 cite, 결론 문장 `strong.key`.
- **결론 문장은 사람이 고른다**: `site/_build/keys.py` 에 글 주소 → 문장 앞부분 목록. 절마다 하나, 도입부가 아니라 결론. 빌드가 못 찾으면 「결론 문장 못 찾음」을 찍는다.
- 이탤릭·밑줄·이모지·따옴표 강조 금지(검사기 T7). 강조 글자 30% 이내.

## 고칠 때

`_src/pages/guide/*.html` 직접 → 빌드·검사 → 인용 수·표 수가 전후 같은지 확인 → 공통_마무리.md

- 수수료·지원금처럼 숫자가 바뀌는 글은 `<title>` 에 연도를 넣고(예: 「배달앱 수수료 2026」), 숫자를 갱신할 때 연도도 같이 올린다. 1페이지를 차지한 제3자 글의 공통점이다(2026-09-19 신호 관찰).
