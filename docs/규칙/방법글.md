# 규칙 · 방법 글 (코스 33편 · 따라 하기)

> 운영자 2026-09-14: "설명은 설명 방법은 방법 … 방법에는 그냥 따라만 하면". 방법 글에는 이유·연구·인용을 본문에 넣지 않는다. 이유는 접힌 상자로만(D36·D37).

## 어디에 무엇

| 것 | 경로 |
|---|---|
| 글 원본 | `site/_src/pages/{local,online,service,foreign}/N-*.html` — **손으로 고치지 않는다.** 생성기가 덮어쓴다 |
| 문안(단계·확인·막히면·근거) | `site/_build/howto/ht_local2.py`(1~5단계)·`ht_local.py`·`ht_online.py`·`ht_service.py`·`ht_foreign.py` |
| 접힌 「이유」 | `site/_build/howto/reasons.py` — `(코스, 파일) → {단계: 이유 HTML}` |
| 화면 캡처 붙이는 자리 | `site/_build/howto/shots_map.py` — `(코스, 파일) → {단계: [(이미지, 설명)]}` |
| 조립기 | `site/_build/howto/howto.py` (`page()`·`kv()`·`inject_reasons()`·`inject_shots()`) |
| 다시 만들기 | `python site/_build/howto/regen.py` → 33편 전부 |
| 절차의 원문 | `marketing-doctor/지식/원전/원문/절차/` (플랫폼 고객센터 43건). 없는 절차는 일반 단계로 쓰고 B 표시 |

## 한 편의 구조 (순서 고정)

1. kicker(코스) · h1(단계 이름) · 한 줄 소개
2. `dl.kv.prep` 준비물·걸리는 시간·돈 — 준비물은 쉼표로 나열하면 목록이 되고 괄호 설명은 한 덩어리(D41)
3. `ol.steps` 따라 하기 — 굵은 한 줄 = 누르는 곳·넣을 값(「스마트플레이스 > 내 업체 > …」식 경로), 아래 한두 문장 보충. 캡처가 있으면 그 단계에. 이유는 `<details class="why">` 기본 닫힘
4. `ul.check` 다 됐는지 확인
5. `dl.kv.stuck` 막히면(Q·A)
6. `p.why` 「왜 하는지는 → 설명 글」 한 줄
7. 이전·다음 단계 상자(빌드가 붙임) · 근거(공식 도움말 URL, 확인 날짜)

## 쓰는 법

- 단계는 **원문 절차**를 옮긴다. 화면 이름·메뉴 이름은 원문 그대로. 원문이 없으면 지어내지 말고 「일반적으로」라 적고 B
- 한 단계 = 한 행동. 「그리고」로 두 행동을 잇지 않는다
- 이유 상자에는 **설명 글에 이미 있는 근거만** 한두 문장 + 그 설명 글 링크. 새 사실 금지
- 검사기는 방법 글의 문장 통계를 건너뛴다(짧은 지시문이 정상). 금지 표현(S1)·연결어미 쉼표(S2-17)는 본다
- 강조는 빌드가 붙인다(D44): 「단추 이름」→ 회색 칩, 돈·기한·한도 숫자 → 형광펜(문단당 1). 문안에서 단추·메뉴 이름은 「」로 적어 두면 칩이 된다(`_build/emphasis.py` UI_TAIL 목록에 없는 이름이면 목록에 더한다)
- 말투는 ko-tone. 「~하세요」 명령형이 기본, 「~해야 합니다」 당위는 법·규정일 때만

## 고칠 때

문안 → `ht_*.py` 의 해당 항목 → `regen.py` → 빌드·검사 → 공통_마무리.md. `_src` 를 직접 고치면 다음 regen 에서 사라진다.

- 막히면 항목을 더할 때는 목록 **끝에** 붙인다. 앞은 그 단계의 핵심 문제(등록·승인·권한) 자리다(2026-09-18, 2단계에서 도구 항목이 앞에 끼어 정리함).
- HOWTO_INDEX 는 단계 순으로 두고, 인쇄용·참고 장(한 장 시리즈·규제 표)은 그룹 **끝**에 붙인다(2026-09-19).
