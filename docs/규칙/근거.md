# 규칙 · 근거 (사실·숫자·인용·원문)

> 언제: 글에 사실·숫자·날짜·인용을 넣거나, 원문을 새로 받을 때. 창고의 자세한 표는 `marketing-doctor/CLAUDE.md` — 이 파일은 사이트 쪽에서 지킬 것만.

## 원칙

1. **창고가 유일한 사실 출처**. `marketing-doctor/지식/` 에 없는 사실은 사이트에 쓰지 않는다. 인터넷에서 본 것을 바로 옮기지 않는다 — 먼저 창고에 원문·레지스트리로 들어가야 한다
2. **인용은 글자 그대로**. `<q>`·`blockquote.official`·「」 안 문장은 `지식/원전/원문/` 보관본과 한 글자도 다르면 안 된다(검사기 Q1). 쉼표 정리·말투 교정도 인용 안은 손대지 않는다(2026-09-15 사고: 정리 스크립트가 인용 안 쉼표를 지워 Q1 5건)
3. **등급을 적는다**. A = 원문을 직접 열어 확인 · B = 2차 자료(언론·요약) · 잠정 = 약한 근거. 글 끝 「근거」에 문서 이름·판본/시행일·등급·확인 날짜
4. **숫자에는 연도와 조사 대상**. 「열 명 중 여덟」식 표현도 출처 줄이 있어야 한다. 첫 화면 「출처 없는 숫자 0」은 빌드가 세는 사실이라 깨면 거짓말이 된다
5. **없는 것은 만들지 않는다**. 사례가 없으면 비워 두고 H13 경고로 남긴다. 「AI 노출 보장」류 주장은 근거 없음으로 적는다
6. 법령은 시행일과 함께. 수수료·요금 숫자는 플랫폼 공식 문서에 있는 것만, 확인 날짜 명기

## 원문 받기

| 무엇 | 어떻게 |
|---|---|
| 도움말·공식 문서 본문 | `node marketing-doctor/엔진/원문받기/fetch_text.mjs URL 저장경로 8000` (헤들리스 Edge, WebFetch 가 막힌 네이버·구글도 열린다). **GitBook 가이드(카카오·당근)는 주소 끝에 `.md` 를 붙여 `curl` 로 받는 게 빠르고 정확하다.** 원문받기를 여러 번 돌린 뒤엔 `python site/_build/cleanup.py` — 2026-09-17 헤들리스 Edge 152개가 남아 옛 탭 내용을 받아 온 적이 있다(edge-ft 프로필) |
| 저장 위치 | `marketing-doctor/지식/원전/원문/<플랫폼>/…md` — 절차는 `원문/절차/<플랫폼>/`. 보관본은 손대지 않는다 |
| 출처 등록 | `지식/원전/레지스트리/*.yaml` 에 서지·등급·URL. 확인 못 한 것은 `확인기록/` 에 「못 했다」로 |
| 네이버 도움말 주소 찾기 | NaverSearch MCP(`search_webkr`)가 서브에이전트보다 빠르다 |
| 인용 대조 | `python marketing-doctor/엔진/quote_check.py` · 사이트는 `site/_build/check.py` Q1 |

## 다른 저장소·자료를 학습할 때

스크래치패드에 클론 → 읽기 → 노트를 `marketing-doctor/지식/문체/` 또는 `조사/` 에 (출처·라이선스·날짜) → 우리 글에 돌려 본 결과 → **적용은 운영자 확인 뒤**. 남의 규칙을 사이트 규칙으로 바로 옮기지 않는다.

- 네이버 검색 MCP(지식iN·웹)가 429(요청 제한)를 내면 그날은 `WebSearch`(허용 도메인을 ftc.go.kr·korea.kr·law.go.kr 처럼 좁혀서)로 공식 문서 주소만 찾고, 본문은 `fetch_text.mjs`·curl 로 받는다(2026-09-18).


- law.go.kr 조문 화면은 iframe이라 못 읽지만, 별표·서식 PDF는 `flDownload.do?flSeq=…` 링크를 curl로 받으면 열린다(2026-09-18, 지방세법 시행령 별표 1). WebSearch(allowed_domains law.go.kr)로 flSeq를 찾는다.
- law.go.kr 조문 본문은 `lsInfoP.do?lsiSeq=<번호>` 를 fetch_text.mjs(헤들리스)로 열면 나온다. lsiSeq 는 `/법령/<한글이름>` 을 curl 해서 `lsiSeq=` 를 grep 한다(2026-09-18).
