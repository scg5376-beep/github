# 질문 프로토콜

질문은 **두 단계**로 나뉩니다.

| 단계 | 질문 | 언제 |
|---|---|---|
| **0단계 · 환경** | S1 도구 구성 · S2 GitHub 연결 | 최초 1회 (이후 확인만) |
| **1단계 · 작업** | Q0 형태 → Q1~Q4 | 매 작업 |

## 원칙
- **0단계가 끝나기 전에는 1단계로 넘어가지 않는다.** `./mp setup` 이 통과해야 한다.
- **Q0는 항상 먼저, 매 작업마다.** 단 이미 저장돼 있으면 "확인 한 줄"로 끝낸다.
- 사용자가 이미 답한 항목은 다시 묻지 않는다(중복 질문 금지).
- 답이 없으면 **추측해서 진행하지 말고** 기본값을 명시하며 되묻는다.
- 3회 이상 되물었는데도 답이 없으면 → `미정` 폴더 저장 + "미정에 넣어뒀습니다" 안내.

# 0단계 · 환경 설정

`./mp setup` 을 먼저 실행한다. 비어 있는 항목을 `[ASK-USER]` 로 알려준다.

## S1 — 도구 구성 (제일 먼저 묻는 질문)

> **이번 작업을 CODEX로만 하시나요? 아니면 클로드코드와 코덱스를 혼합해서 쓰시나요?**
> - **CODEX 단독** — 질문·설계·생성·정리·커밋을 코덱스가 전부 처리합니다. 빠르고 단순해요.
> - **클로드코드 + 코덱스 혼합** — 클로드가 지시서를 만들고 코덱스가 생성·커밋합니다.
>   지시와 검수가 기록으로 남아서, 컷이 많거나 여러 프로젝트를 병행할 때 좋아요.

| 답 | 저장 | 실행 모드 | 절차 |
|---|---|---|---|
| 코덱스만 / 단독 / 하나로 | `tools: codex` | `run_mode: solo` | `06-mode-solo.md` |
| 혼합 / 클로드도 씀 / 둘 다 | `tools: mixed` | `run_mode: relay` | `07-mode-relay.md` |
| 모르겠다 | — | — | **CODEX 단독을 권한다** (나중에 한 줄로 전환 가능) |

```bash
./mp setup --tools codex     # 또는 --tools mixed
```

## S2 — GitHub 연결

> **작업물을 어느 GitHub 레포에 저장할까요?**
> (예: `https://github.com/내아이디/my-masterpiece-studio.git`)

| 상황 | 행동 |
|---|---|
| 주소를 안다 | `./mp setup --repo <주소>` — profile 저장 + `origin` 설정 |
| 이미 clone 한 폴더에서 작업 중 | `git origin` 을 자동 인식한다. 그대로 진행 |
| **모른다 / 레포가 없다 / 답이 애매하다** | **`./mp setup --guide` 를 실행해 "레포 만들기부터" 안내한다** |
| origin 과 저장된 주소가 다르다 | 어느 쪽이 맞는지 묻고 `--repo` 로 정정 |

레포가 없는 사용자에게는 **먼저 만들게 하고, 연결까지 확인한 뒤** 작업을 시작한다.
계정 생성 → Fork 또는 새 레포 → clone → `--repo` 연결 → 첫 커밋으로 확인.
자세한 절차는 `08-setup-github-connect.md`.

# 1단계 · 작업 질문

## Q0 — 마스터피스 형태 (최상위, 항상 유지)

**처음 사용자:**
> 시작 전에 딱 한 번만 여쭤볼게요. 다섯 가지 마스터피스를 각각 **어떤 형태**로 쓰고 계신가요?
> 1) 캐릭터 — 텍스트 프롬프트 / 참고이미지+프롬프트 / LoRA / 캐릭터시트
> 2) 룩북 — 룩 리스트(텍스트) / 룩별 참고이미지 / 무드보드
> 3) 배경 — 장소 프롬프트 / 배경판 이미지 / 3D 레퍼런스
> 4) 카메라구도 — 앵글+렌즈 텍스트 / 콘티 썸네일 / 샷리스트
> 5) 원근설정 — 1·2·3점 투시 / 심도·보케 / 렌즈 왜곡 프리셋
> (모르시면 "기본"이라고만 답해주세요 → 전부 텍스트 프롬프트 형태로 설정합니다.)

→ 답을 `profile.yaml`의 `masterpiece_forms.<종류>.form` 에 저장하고 `updated` 갱신.

**재방문 사용자:**
> 저장된 마스터피스 형태(캐릭터=참고이미지+프롬프트, 룩북=룩 리스트 …) 그대로 진행할까요?

---

## Q1 — 제공 vs 생성
> 이번 작업에 쓸 마스터피스를 **가지고 계신가요(제공)**, 아니면 **새로 만들까요(생성)**?

| 답 | 행동 |
|---|---|
| 제공 | 파일/텍스트를 받아 `new_masterpiece.py` 로 카드화 후 커밋 |
| 생성 | 사용자 설명을 받아 프롬프트를 작성 → 카드 생성 |
| 섞임 | 종류별로 나눠서 처리 (예: 캐릭터는 제공, 배경은 생성) |

---

## Q2 — 자산축적 vs 작업만
> 작업이 끝나면 이 조합을 **자산으로 쌓아둘까요(다음에 재사용)**, 아니면 **이번 작업만** 할까요?

| 답 | 행동 |
|---|---|
| 자산축적 | 새 카드 + `recipes/RC-###.yaml` 저장, `index.py` 갱신 후 커밋 |
| 작업만 | `outputs/` 결과물만 남김. 카드/레시피 생성 안 함 |

---

## Q3 — 이미지 저장 폴더
> CODEX가 만든 이미지를 어디에 저장할까요? (예: `outputs/projects/2026-08-아리-카페`)
> 정하지 않으시면 `outputs/_unsorted/미정` 에 넣어두고 나중에 옮길 수 있어요.

- 답이 있으면 그 경로를 `--project` 또는 `--dest` 로 사용.
- 무응답 → `organize.py --undecided`, 그리고 결과를 알려준다.

---

## Q4 — 자동매칭 vs 수동지정
> 배경·카메라·원근을 **AI가 자동으로 골라도 될까요(자동)**, 아니면 **직접 지정**하실래요(수동)?

| 답 | 행동 |
|---|---|
| 자동 | `--mode auto` — 캐릭터 태그 + 무드로 점수 매겨 선택. 선택 결과를 사용자에게 **보고**한다 |
| 수동 | `--mode manual` — 빠진 항목이 있으면 그 항목만 다시 묻는다 |

> RELAY(혼합)에서는 Claude가 Q1~Q4의 답을 `--answers` 로 오더에 실어 보낸다.
> **CODEX는 오더에 적힌 답을 다시 묻지 않는다.**

## 무응답 / 모호 처리 요약

| 상황 | 처리 |
|---|---|
| 도구 구성 무응답 | CODEX 단독(SOLO)을 권하고 이유를 한 줄로 설명 |
| GitHub 연결 무응답/모름 | `./mp setup --guide` 로 **레포 생성부터** 안내. 연결 확인 전엔 작업 시작 금지 |
| 유형 미지정 카드 | `[ASK-USER]` → 되묻기 → 무응답 시 `masterpieces/_unsorted/미정/` |
| 저장 폴더 미지정 | 되묻기 → 무응답 시 `outputs/_unsorted/미정/` |
| 이름이 여러 카드와 겹침 | 후보 ID를 나열하고 하나 고르게 함 |
| 룩 키(L1 등) 없음 | 사용 가능한 키 목록을 보여주고 다시 묻기 |
| RELAY인데 열린 오더가 이미 있음 | 새 오더를 만들지 말고 기존 오더 처리부터 안내 |
