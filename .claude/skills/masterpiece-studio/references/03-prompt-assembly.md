# 프롬프트 조립 규칙

## 조립 순서 (고정)
```
캐릭터 → 룩(의상) → 배경 → 카메라구도 → 원근설정 → 포즈 → 무드
```
앞에 올수록 우선순위가 높다. 이미지 모델은 앞쪽 토큰을 더 강하게 반영하므로,
**정체성(캐릭터) → 외형(룩) → 공간(배경) → 촬영(카메라·원근)** 순서를 바꾸지 않는다.

각 요소는 ` / ` 로 구분해 이어붙인다.

## 고정 요소(lock)
캐릭터 카드의 `lock` 은 프롬프트 본문과 **별도로** "고정 요소(절대 변경 금지)" 항목에 실린다.
CODEX에 넘길 때 이 문구를 함께 전달해 컷 간 일관성을 유지한다.

## 네거티브 병합
모든 카드의 `prompt.negative` 를 모아 **중복 제거 후 쉼표로 병합**한다.
(순서 유지: 캐릭터 → 배경 → 카메라 → 원근)

## 포즈 뱅크
`--mood` 문자열에 아래 키워드가 포함되면 해당 포즈 세트를 순환 사용한다.

| 키워드 | 포즈 세트 |
|---|---|
| `귀엽` | 고개 기울인 미소, 볼 감싸기, 브이, 손하트, 뒤돌아 눈웃음, 앉아 다리 흔들기, 컵 감싸쥐기, 폴짝 |
| `시크` | 팔짱 정면, 벽에 기대기, 걸어오며 뒤돌기, 턱 괴기 |
| `활동` | 달리기, 점프 착지, 돌아서며 머리 날림, 하이파이브 |
| `차분` | 창밖 응시, 책 읽는 옆모습, 정면 스탠딩, 눈 감고 미소 |
| (없음) | 정면 스탠딩, 3/4 반신, 앉은 자세, 뒤돌아보기 |

`--poses "포즈1,포즈2"` 로 직접 넘기면 뱅크를 무시한다.

## 컷 수 계산
전체 조합 = `룩 수 × 카메라 수 × 원근 수`

- `--count` 가 조합보다 **작으면** 균등 간격으로 샘플링(치우침 방지).
- `--count` 가 조합보다 **크면** 조합을 순환하되 포즈가 매 컷 달라진다.
- `--count` 생략 시 전체 조합을 모두 만든다.

## 자동매칭(--mode auto) 점수식
```
점수 = (캐릭터 태그 ∩ 카드 태그) × 2  +  무드 키워드가 카드 본문에 등장한 횟수
       + min(use_count, 5) × 0.1
```
동점이면 ID 오름차순. **자동 선택 결과는 반드시 사용자에게 보고한다.**

## 충돌 해결
| 충돌 | 처리 |
|---|---|
| 배경 광원 vs 카메라 심도 | 카메라 설정 우선(뒤쪽이 촬영 지시) |
| 룩 색상 vs 캐릭터 lock 색상 | **lock 우선.** 룩에서 해당 색 지정 문구 제거 |
| 원근과 프레이밍 모순 (예: 클로즈업 + 1점투시 강조) | 프레이밍 우선, 원근은 "배경 처리"로 약화 |
