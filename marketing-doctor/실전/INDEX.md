# 실전 데이터

> **여기는 지식창고가 아니다.** 지식창고(`../지식/`)는 남의 문서에서 온 것이고,
> 여기는 **우리가 실제로 해서 나온 것**이다. 섞지 않는다.
>
> 여기 쌓인 것이 `../지식/판매경로/무엇을-세야-하나.md` 의 「아직 못 채운 것」을
> 채워 간다. **국내 전환율·객단가 기준값은 사 오는 게 아니라 여기서 만들어진다.**

## 한 방향이다

```
품목 레포   보고/ 세 파일을 채운다      ← 기록의 원본. 여기서만 고친다
            ↓  보낸다
컨트롤 타워  품목/ 에 그대로 놓는다      ← 손대지 않는다
            ↓  검사한다 (엔진/report_check.py)
            분석/ 에 분석 노트를 쓴다   ← 제안까지만. 실행은 품목 레포가 정한다
```

**컨트롤 타워는 품목 레포에 쓰지 않는다.** 자세한 건 [워크플로우.md](워크플로우.md).

## 이 폴더에 무엇이 있나

| 곳 | 무엇 |
|---|---|
| [워크플로우.md](워크플로우.md) | **먼저 읽는다.** 계약 폴더 · 보내는 법 · 검사 · 분석 범위 |
| [양식/](양식/) | 품목 레포의 `보고/` 에 복사해 갈 세 파일 |
| [품목/](품목/) | 받은 보고가 그대로 놓이는 자리. `_예시/` 에 채워진 모습이 있다 |
| [품목/안경-오프라인/](품목/안경-오프라인/) | **첫 검증 데이터** (2026-09-04~). 기준선 커밋 992eb62 |
| [분석/](분석/) | 컨트롤 타워가 쓰는 분석 노트 |

## 계약은 세 파일이다

```
품목.yaml   품목카드. 시작할 때 한 번. 자리 0 체크 · 판단지표 · 안 하기로 한 것
주간.csv    한 주 한 줄. 숫자만. 헤더가 고정이다
기록.md     숫자로 안 잡히는 것. 무엇을 왜 바꿨나
```

**이름과 모양이 품목마다 다르면 분석을 못 한다.** 양식을 그대로 쓴다.

## 받을 때 반드시

```bash
python3 엔진/report_check.py        # 실전/품목/ 아래 전부
```

**통과하지 못한 보고는 분석하지 않는다.** 컨트롤 타워가 대신 고치지 않고
품목 레포에 다시 채워 달라고 돌려보낸다.

## 여기 적지 않는 것

```
❌ 손님 이름·전화번호·주소     개인정보다. 집계된 수만 적는다
❌ 매장 상호·지역             엔진/brand_check.py 가 잡는다 (csv 도 검사한다)
❌ "이렇게 하면 오른다" 는 단정  12주로 인과는 말할 수 없다
```

## 언제 지식창고로 올라가나

```
사례 1개    여기 실전/ 에만 둔다
사례 3개 넘고 방향이 같으면   ../지식/실무/ 로 올린다 ("이렇게 해서 됐다" 로 쓴다)
표본이 늘고 반증까지 하면      ../지식/개념-*/ 승급을 검토한다
```

기준은 `../지식/출처등급.md` 와 `../지식/학습계획.md` 의 재확인 주기를 따른다.
