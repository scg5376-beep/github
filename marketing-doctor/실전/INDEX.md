# 실전 데이터

> **여기는 지식창고가 아니다.** 지식창고(`../지식/`)는 남의 문서에서 온 것이고,
> 여기는 **우리가 실제로 해서 나온 것**이다. 섞지 않는다.
>
> 여기 쌓인 것이 `../지식/판매경로/무엇을-세야-하나.md` 의 「아직 못 채운 것」을
> 채워 간다. **국내 전환율·객단가 기준값은 사 오는 게 아니라 여기서 만들어진다.**

## 레포가 둘로 나뉜다

```
marketing-doctor  (여기)   컨트롤 타워
                           · 지식을 모으고 갱신한다
                           · 실전 데이터를 받아 쌓는다  ← 이 폴더
                           · 품목 레포가 가져갈 스킬을 만든다 (.claude/skills/)

품목-○○  (따로)            실행·실험
                           · 스킬을 복사해 간다
                           · 실제로 글 쓰고 광고 돌리고 판다
                           · 주간 기록을 채워 여기로 되돌려 보낸다
```

**실험은 저기서, 보존과 학습은 여기서.** 품목 레포가 늘어도 판단 기준은 한 곳이다.

## 이 폴더에 무엇이 있나

| 파일 | 무엇 |
|---|---|
| [양식-품목카드.md](양식-품목카드.md) | 품목 하나를 시작할 때 **한 번** 채운다 |
| [양식-주간기록.md](양식-주간기록.md) | 매주 한 줄씩 채운다. 이게 데이터의 전부다 |
| [품목/](품목/) | 되돌아온 기록이 쌓이는 자리 |

## 어떻게 되돌려 보내나

```
1  품목 레포에서 양식-주간기록 을 채운다
2  주 1회, 그 내용을 여기 품목/<품목이름>.md 에 이어 붙인다
3  파일이 6,000자를 넘으면 품목/<품목이름>/ 폴더를 만들어 반기로 나눈다
   (기준: ../기준/파일정리규칙.md)
```

**붙여넣기로 충분하다.** 자동 연동을 만들지 않는다 — 만드는 순간 관리 대상이 하나 는다.

## 여기 적지 않는 것

```
❌ 손님 이름·전화번호·주소     개인정보다. 집계된 수만 적는다
❌ 매장 상호·지역             엔진/brand_check.py 가 잡는다
❌ "이렇게 하면 오른다" 는 해석  기록은 기록이다. 해석은 사례가 셋 넘을 때 ../지식/실무/ 로
```

## 언제 지식창고로 올라가나

```
사례 1개    여기 실전/ 에만 둔다
사례 3개 넘고 방향이 같으면   ../지식/실무/ 로 올린다 ("이렇게 해서 됐다" 로 쓴다)
표본이 늘고 반증까지 하면      ../지식/개념-*/ 승급을 검토한다
```

기준은 `../지식/출처등급.md` 와 `../지식/학습계획.md` 의 재확인 주기를 따른다.
