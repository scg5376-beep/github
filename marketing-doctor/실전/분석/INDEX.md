# 분석 노트

> **월 1회.** 파일 이름은 `<품목>-YYYY-MM.md`.
> 여기 쓴 것은 **제안까지**다. 실행 여부는 품목 레포가 정한다.
> 분석 범위와 한계는 `../워크플로우.md`.

## 쓰기 전에

```bash
python3 엔진/report_check.py
```

**통과 못 하면 분석하지 않는다.** 검사에서 "분석에서 뺀다" 고 나온 주는 실제로 뺀다.

## 노트 틀

```
── <품목> · 2026-__

받은 것        주차 __개 (__~__)  ·  검사 결과: 통과 / 제외한 주 __개

숫자
  직접유입 비율    __% → __%  (지난달 → 이번달)
  정산액          ______원 → ______원
  주문            __건 → __건
  ⚠️ 모르는 칸     (빈칸으로 온 항목을 적는다. 0 이 아니다)

바꾼 것과 그 다음
  W__ ______ 을 바꿈 → 다음 2~3주: ______
  ※ 같이 움직였다는 것뿐이다. 원인이라고 쓰지 않는다

기록의 구멍
  (빈 주 · 한 주에 둘 이상 바꾼 주 · 안 세고 있는 칸)

제안
  1.
  2.
  ※ 근거가 창고에 있으면 파일 이름을 적는다. 없으면 "근거 없음, 해보자는 것" 이라고 적는다
```

## 쓸 때 지키는 것

**① 인과로 쓰지 않는다.** 무작위 실험이 아니다. "같이 움직였다" 까지다.

**② 업종 평균과 비교하지 않는다.** 그 기준값이 창고에 없다.
없는 숫자를 끌어다 쓰면 이 창고의 값어치가 사라진다(절대 규칙 1).

**③ 비교는 자기 자신과 한다.** 지난달의 같은 품목, 그리고 다른 품목의 같은 자리.

**④ 품목이 셋을 넘기 전에는 일반화하지 않는다.**
한 품목에서 보인 것은 우연일 수 있다.
