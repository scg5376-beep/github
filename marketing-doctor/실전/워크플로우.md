# 보고 워크플로우

> **컨트롤 타워는 품목 레포에 쓰지 않는다.** 읽고 분석만 한다.
> 분석 결과도 품목 레포에 밀어 넣지 않고 **여기 `분석/` 에 쓴다.**
> 품목 레포가 그걸 보고 스스로 정한다.

## 왜 한 방향인가

양쪽에서 고치면 **어느 쪽이 맞는지 알 수 없게 된다.**
그건 이 창고가 계속 잡아 온 오류의 모양이다 — 같은 표가 두 벌이면
낡은 쪽을 보고 판단하게 된다.

```
품목 레포   기록의 원본을 가진다        ← 여기서만 고친다
컨트롤 타워  스냅샷을 받아 분석한다      ← 여기서는 절대 고치지 않는다
```

## 누구를 위한 것인가 — 컨트롤 타워의 검증 데이터다

**`보고/` 는 품목 레포를 위한 게 아니다.** 이 창고가 세운 이론(`../지식/판매경로/`)이
실제로 맞는지 보려고 받는 **검증 데이터**다. 품목 레포는 자기 기록을 자기 방식대로 갖고,
거기에 이 그릇 하나를 더 얹을 뿐이다.

그래서 **품목이 지금 오프라인 매장이든, 아직 온라인 판매가 없든 그대로 얹는다.**
안 세는 칸은 빈칸으로 둔다 — 그건 이미 계약이 허용한다(0 과 모름은 다르다).
이커머스로 넓혀 가면 그때 칸이 채워진다. **칸을 그 품목에 맞춰 갈지 않는다** —
갈면 품목마다 모양이 달라져서 나란히 놓고 볼 수 없게 된다.

> 2026-09-02 에 실제로 헷갈렸다. 첫 실전 대상이 오프라인 매장이라 "칸이 안 맞으니
> 갈아야 한다" 고 했는데, 운영자가 바로잡았다 — 이건 검증용이고 그 매장은 이커머스로
> 넓혀 가는 중이다. **그릇은 그대로, 빈칸은 빈칸으로.**

## 품목 레포에 두는 계약 폴더 — `보고/`

**이름과 파일 셋이 고정이다.** 품목마다 다르게 만들면 분석을 못 한다.

```
보고/
  품목.yaml     품목카드. 시작할 때 한 번 쓰고 거의 안 고친다
  주간.csv      한 주 한 줄. 숫자만
  기록.md       숫자로 안 잡히는 것. 무엇을 왜 바꿨나
```

### 주간.csv — 헤더가 고정이다

```
주차,시작일,바꾼것,광고비,노출,발행,방문,주문,정산액,직접유입주문,신규리뷰,답글,비고
```

```
· 주차       2026-W37 형식
· 바꾼것     한 주에 하나. 없으면 "없음"
· 정산액     수수료를 뺀 실수령액. 결제금액이 아니다
· 직접유입주문  판매자 마케팅 수수료가 붙은 주문 건수
· 모르는 값   빈칸으로 둔다. 0 으로 적지 않는다 — 0 과 모름은 다르다
```

**빈 주도 한 줄 넣는다.** "아무것도 안 함" 이 데이터다.

## 어떻게 보내나

```
1  품목 레포에서 보고/ 세 파일을 채운다
2  컨트롤 타워로 보낸다 — 셋 중 편한 방법
     · 대화창에 붙여넣기          가장 간단하다
     · 파일로 올리기
     · 레포를 세션에 붙이기        읽기 권한만 있으면 된다
3  컨트롤 타워가 실전/품목/<품목>/ 에 그대로 놓는다  ← 손대지 않는다
4  python3 엔진/report_check.py 로 검사한다
5  통과하면 분석한다
```

**자동 연동을 만들지 않는다.** 만드는 순간 관리 대상이 하나 늘고,
그게 고장 나면 데이터가 조용히 끊긴다.

## 검사에서 걸러 내는 것

`엔진/report_check.py` 가 본다.

```
· 헤더가 계약과 다른가
· 주차가 빠졌거나 겹치는가
· 한 주에 둘 이상 바꿨는가        ← 그 주는 분석에서 제외한다
· 정산액 없이 주문만 적혔는가
· 손님 정보·상호·전화번호가 섞였는가  (brand_check 규칙을 그대로 쓴다)
```

**개인정보가 하나라도 걸리면 받지 않는다.** 지우고 다시 보낸다.

## 분석은 무엇을 말하나

```
말할 수 있다   · 직접유입 비율의 추세
              · 바꾼 것과 그 다음 2~3주가 같이 움직였나
              · 품목끼리 비교 (같은 자리에서 무엇이 달랐나)
              · 기록 자체의 구멍 (빈 주 · 규칙 위반 · 안 세고 있는 칸)

말할 수 없다   · "이것 때문에 올랐다" — 무작위 실험이 아니다
              · 업종 평균과의 비교 — 그 기준값이 창고에 없다
```

분석 노트는 `분석/<품목>-YYYY-MM.md` 에 쓴다.
**노트는 제안까지만이다.** 실행 여부는 품목 레포가 정한다.

## 주기

```
주 1회    품목 레포가 보고/ 를 채운다            (5분)
월 1회    컨트롤 타워가 받아서 검사·분석한다      (분석 노트 한 장)
12주      계속·조정·중단을 판단한다              (품목카드에 적어 둔 지표로)
```

**주 단위로 분석하지 않는다.** 주간 변동은 대부분 잡음이라
매주 들여다보면 없는 패턴을 보게 된다(우리가 붙인 것).

## 여러 품목이 모이면

품목이 셋을 넘으면 같은 자리를 나란히 놓고 본다.
**한 품목에서 보인 것은 우연일 수 있고, 셋에서 같은 방향이면 다르다.**

```
사례 1개    실전/ 에만 둔다
사례 3개 넘고 방향이 같으면   ../지식/실무/ 로 올린다 ("이렇게 해서 됐다")
표본이 늘고 반증까지 하면      ../지식/개념-*/ 승급을 검토한다
```

## 이 워크플로우가 지키는 한 줄

**기록은 품목 레포가, 판단 기준은 컨트롤 타워가.**
둘이 섞이면 품목이 늘수록 무엇이 맞는지 모르게 된다.
