## 네이버가 무엇을 해 준다고 말하나

> 검색엔진 최적화 작업은 여러분의 사이트 내 콘텐츠 정보를 검색엔진이 잘 이해할 수 있도록 정리하는 작업입니다. 이 작업을 통하여 사이트 내 콘텐츠가 네이버의 검색 결과에 누락되지 않도록 조치할 수 있으며, 무엇보다 사용자가 원하는 콘텐츠의 내용을 명확하게 네이버 검색엔진에게 알려 줄 수 있습니다.

> 네이버 검색은 검색엔진에 친화적인 사이트를 우대합니다.

**"우대한다" 고 네이버가 직접 적었다.** 다만 이건 **친화적인 사이트**에 대한 것이지
순위를 보장한다는 말이 아니다(우리가 붙인 것).

## ★ 등록은 노출 조건이 아니다

> 네이버 웹 검색은 웹 수집 로봇이 자동으로 수집한 사이트 정보를 반영하여 노출하고 있습니다. 따라서 검색 등록 절차는 존재하지 않습니다.

> 네이버 웹마스터도구에 사이트를 등록하지 않아도 네이버 검색 결과에 사이트 및 웹문서들이 반영됩니다. 하지만, 네이버 웹마스터도구에 사이트 등록후 소유확인절차를 진행하면, 사이트내 콘텐츠의 수집, 색인, 노출정보를 리포트를 통해서 파악 할 수 있습니다.

**대행사가 파는 "네이버 사이트 등록" 은 노출을 만들어 주지 않는다.** 등록·소유확인의 값어치는
**내 사이트가 얼마나 수집·색인·노출되는지 리포트로 보는 것**에 있다(우리가 붙인 것).

## 등록은 호스트 단위다 — 여기서 많이 막힌다

> 사이트 등록은 호스트 단위만 지원합니다.

```
http://www.mysite.com     (O)
http://blog.mysite.com    (O)
http://www.mysite.com/myid (X)
```

★ **남의 플랫폼 안의 내 페이지는 등록이 안 된다.** 스마트스토어 주소나 카페 게시판 주소를
넣으려다 막히는 이유가 이것이다(우리가 붙인 것).

> 사이트의 소유 확인은 HTML의 meta 태그를 활용하는 방법 혹은 HTML 파일 업로드를 통해서 진행할 수 있습니다.

## 소유확인 메타태그 — 검증에서 빠지는 자리

> 소유확인은 자바스크립트 실행을 지원하지 않으니 마크업 확인은 최신 웹브라우저의 URL 입력란에 view-source:사이트_URL 을 입력하거나 페이지 소스보기를 활용하시기 바랍니다.

**화면에 보이는 것과 소스가 다를 수 있다.** 빌더가 넣어 준 태그가 실제 소스에 없으면 확인이 안 된다.

> 서치어드바이저에서 소유확인용 메타태그 검증 시 자바스크립트, meta refresh, cookie 를 활용한 브라우저단의 리다이렉션은 지원하지 않습니다. 리다이렉트가 필요하다면 웹서버에서 처리되는 http 리다이렉트 (301, 302)로 처리해주세요.

> 소유확인용 메타태그 정보가 html frame 태그 내에 존재 시 검증에서 제외 처리합니다. frame 태그가 아닌 html head 태그 내에 기입해 주세요.

> 소유확인용 메타태그 정보가 html body 태그 내에 존재 시 검증에서 제외 처리합니다. html head 태그 내에 기입해 주세요.

```
head 안에 <meta name="naver-site-verification" content="…"/>   ← 여기여야 한다
body 안 · frame 안 · 리다이렉트되는 페이지                      ← 전부 검증 제외
```

## 소유 확인이 안 되는 다섯 가지

```
1. 방화벽에서 네이버 검색로봇을 차단
2. 메인 페이지가 자바스크립트·meta refresh 로 redirect
3. frame 태그 안에 확인용 태그를 넣음
4. 업로드용 원본 HTML 파일이 손상됨
5. 인터넷 익스플로러 11 미만
```

> 사이트의 메인 페이지가 자바스크립트 혹은 meta refresh 기법을 사용하여 redirect 된다면 지원이 불가능합니다. HTTP redirect 방식을 사용해 주세요.

## 로봇 이름은 Yeti — 그리고 IP로 막지 말라고 한다

```
User-agent: Yeti
Allow: /
```

> 부득이하게 검색 로봇을 차단해야 하는 경우 IP 기반으로 차단하지 마세요. 검색 로봇의 IP 대역은 언제든지 변경될 수 있습니다.

**보안업체가 IP로 봇을 막아 두면 검색에서 사라진다.** 이 문장이 그 자리다(우리가 붙인 것).

## ★ 여러 사이트를 만들면 불이익이다

> 검색 노출량을 늘이기 위하여 동일한 콘텐츠로 구성된 여러 개의 사이트를 개설하는 경우가 있습니다. 이 경우 검색 노출에 불이익을 받을 수 있으니 유의하세요.

> 모든 페이지의 제목을 동일하게 표현하지 마세요. 페이지의 제목은 콘텐츠 주제를 정확하게 설명할 수 있는 문구를 적어야 합니다.

★ **"지점마다 사이트를 따로 만들라" 는 조언이 여기에 정면으로 걸린다.**
블로그 쪽 A등급 문서의 유사 문서 로직과 같은 방향이다
(`../플랫폼/네이버/네이버가-검색에서-빼는-글.md`).

## 사이트맵과 RSS

> 사이트 내의 최신글은 본문 전체를 포함하여 RSS 피드에 담아주세요.

사이트맵은 수집 대상 URL 목록을 담은 XML 파일이고, 웹마스터도구의 요청 메뉴에서 낸다.

## 언제 반영되나

> 네이버의 검색로봇이 방문한 뒤 최대 1주일 이내에 사이트의 콘텐츠가 검색에 반영됩니다.

`site:내주소` 로 확인한다. **일주일은 기다려 보고 나서 문제를 찾는다**(우리가 붙인 것).

## 안 보일 때 — 원인이 층마다 다르다

### 메인이 안 보이면

> 메인 페이지의 meta 태그에 noindex 처리가 되어있다면 해제해주세요. noindex가 표기된 페이지는 검색 반영에서 제외됩니다.

> (예외적으로 공공기관, 교육기관 등 공공재 성격의 사이트 및 사용자의 선호도가 높은 사이트는 내부 정책에 따라 검색 반영이 될 수 있습니다)

★ **예외가 있다고 네이버가 밝혔다.** 공공기관·교육기관 같은 공공재 성격 사이트와
**사용자의 선호도가 높은 사이트**는 noindex 라도 반영될 수 있다.

> 사이트 제목과 설명은 검색엔진에서 엄격하게 관리하고 있으므로 정책에 위반되는 항목이 없는지 HTML 마크업 가이드를 다시한번 참고하세요.

frame 태그로 메인을 감싸는 것도 원인으로 든다.
**여기서 가리키는 「HTML 마크업 가이드」의 제목·설명 규칙은** → `홈페이지-제목과-설명-어떻게-쓰나.md`.

### 글이 반영이 안 되면

> 페이지 내의 모든 콘텐츠가 자바스크립트로 로딩되는 구조인지 확인하세요. 대부분의 검색엔진은 표준 HTML 마크업을 사용하여 콘텐츠를 제공하는 것을 권장합니다.

★ **AI로 만든 사이트가 여기 걸린다.** 화면에는 보이는데 검색로봇에게는 빈 페이지다
(`홈페이지-AI로-만들면.md`). frame, 자바스크립트 redirect 도 같은 항목에 있다.

### 반영되는 문서 수가 적으면

> 웹마스터도구에 제출된 사이트맵 및 RSS 가 올바르게 표기되었는지 확인해주세요. 특히, 제출된 사이트맵 및 RSS 내의 링크가 상대 경로로 지정되어 있는 경우, 링크의 호스트가 등록된 사이트와 일치하지 않는 경우 수집을 진행하지 않습니다.

> 페이지의 meta 태그에 nofollow 처리가 되어있다면 해제해주세요. nofollow가 표기된 페이지의 경우 페이지 내 링크 수집을 진행하지 않습니다.

> 페이지들의 링크 처리 시 자바스크립트만을 사용하면, 검색로봇이 어떤 URL 인지 정확하게 파악할 수 없어서 이후의 다른 좋은 정보들을 찾아갈 수 없는 문제가 있습니다. 네이버의 검색로봇에게 여러분의 사이트 내부 페이지를 잘 알려주기 위해서는 표준에 맞는 링크 URL정보를 제공하는 것을 권장합니다.

```
<a href="http://www.A.com">Link</a>          로봇이 URL 을 안다
<span onClick="javascript:goto(A)">Link</span>  로봇이 URL 을 모른다
```
