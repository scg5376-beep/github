# 출처 등급과 인용 규칙

> 이 지식베이스는 "증명된 것"을 파는 자산이다.
> 인용 하나가 틀리면 나머지 전부의 신뢰가 같이 무너진다.
> 그래서 **확인한 만큼만 쓰고, 확인 안 된 것은 그렇다고 적는다.**

## 축이 두 개다

한 축으로는 못 가른다. **누가 그렇게 말했는지**와 **그 말이 맞는지**는 다른 문제다.

```
        근거 ──────────────────────────────────────────►
출처    │     실증          공식         실무        추측
 │      │  (대규모 데이터) (본인이 밝힘) (해봤더니)  (그럴 것)
 ▼      │
  A     │  단정해도 됨    "~라고 밝힘"  "~라고 함"  쓰지 않음
  B     │  "~라고 한다"   "~라고 밝힘"  "~라고 함"  쓰지 않음
  C     │  쓰지 않음      쓰지 않음     쓰지 않음   쓰지 않음
```

유튜버가 "주 3회 써야 한다" 고 말한 영상을 봤다면 **출처는 A**(본인이 그렇게 말한 게
확실하다). 그런데 **근거는 실무**다(그 사람 경험일 뿐, 검증된 게 아니다).
이 둘을 안 가르면 "출처 있는 주장" 이라며 검증 안 된 말을 단정하게 된다.

## 출처 등급 — 누가 그렇게 말했나

| 등급 | 뜻 | 글에 쓸 때 |
|---|---|---|
| **S** | A + 독립 출처 수렴 + 반증 시도 + 숫자에 연도·표본 | **이 창고의 자산.** 이걸로 글의 기둥을 세운다 |
| **A** | 원문·공식 문서를 직접 확인. URL 있음 | 저자·연도까지 밝히고 단정해도 된다 |
| **B** | 신뢰할 만한 2차 자료 여럿이 일치. 원문 미확인 | "~로 알려져 있다" 로 쓴다. 저자·연도 단정 금지 |
| **C** | 업계 통설이나 출처 불명 | **글에 쓰지 않는다.** 확인 후 승급 |

## S 는 무엇이 다른가

A 는 **"내가 원문을 봤다"** 는 뜻일 뿐이다. 원문이 틀렸을 수도 있다.
한 연구, 한 보고서에만 기대면 그게 뒤집힐 때 그 위에 쓴 글이 전부 무너진다.

S 는 **하나가 무너져도 안 무너지는 지식**이다. 네 가지를 다 채워야 한다.

```
① 원문 확인          A 조건을 이미 충족
② 독립 출처 2곳 이상  서로 베낀 게 아닌 곳에서 같은 결론이 나온다
③ 반증 시도          "이게 틀렸다는 자료" 를 찾아봤고, 결과를 적어뒀다
④ 숫자에 꼬리표       연도 · 조사기관 · 표본 크기가 붙어 있다
```

**③이 핵심이다.** 맞는 자료만 모으면 확신만 커지고 정확도는 안 커진다.
반증을 찾아보고 **못 찾았다는 사실까지 적어야** S다. 찾았으면 그것도 적는다.

| 안 적으면 | 이렇게 된다 |
|---|---|
| 반증을 안 찾아봄 | 3년 뒤에 "그거 반박된 지 오래인데요" 를 듣는다 |
| 표본을 안 적음 | 30명 설문이 국민 통계처럼 인용된다 |
| 연도를 안 적음 | 2019년 숫자로 2026년을 설명하게 된다 |

**실무 근거는 구조적으로 S가 될 수 없다.** 표본이 하나라 ②를 못 채운다.
그게 맞다. 실무는 실무의 자리에 둔다.

## 근거 유형 — 그 말이 맞다는 근거가 뭔가

| 유형 | 뜻 | 예 |
|---|---|---|
| **실증** | 대규모 데이터·통계·논문 | 996개 캠페인 분석 · 정부 실태조사 |
| **공식** | 플랫폼·기관이 자기 규칙을 직접 밝힘 | 네이버 고객센터 · 구글 검색센터 |
| **실무** | 해본 사람의 경험 | "주 3회 2달 하니 올라왔다" |
| **추측** | 근거 없이 도는 말 | "네이버는 이런 글을 좋아한다더라" |

**공식을 실증처럼 쓰지 않는다.** 네이버가 "우리는 이렇게 한다" 고 말한 것은
**그렇게 말했다는 사실**만 확실하다. 실제로 그런지는 검증할 방법이 없다.
다만 그 규칙을 따르는 건 합리적이다 — 그 회사가 자기 서비스를 설명한 것이니까.
그래서 인용은 **"네이버는 ~라고 밝힌다"** 로 한다. **"네이버는 ~한다"** 가 아니다.

**실무를 실증처럼 쓰지 않는다.** 실무는 표본이 하나다. 그 매장에서 통한 게
다른 업종·지역에서도 통한다는 보장이 없다.

다만 **실무를 버리지도 않는다.** 실증만으로는 "그래서 내일 뭘 하냐" 에 답이 안 된다.
대신 **자리를 나눠 둔다** — 실증은 `개념-*/`, 실무는 `실무/`.
섞어 두면 나중에 어느 게 검증된 건지 구분이 안 된다.

## 규칙

0. **애매하면 멈추지 말고 더 판다.** 애매한 채로 등급을 매기지 않는다.
   확인이 안 되면 등급을 낮추는 게 아니라 **조사를 계속한다.**
1. **C등급은 발행하지 않는다.** 확인해서 A나 B로 올린 뒤에 쓴다.
2. **B등급은 숫자를 단정하지 않는다.** "60:40 이라고 한다" ⭕ / "60:40 이다" ❌
3. **출처는 `원전/레지스트리/` 의 해당 묶음 yaml 한 곳에만 적는다.** 개념 파일은 `출처: EB-01` 처럼 ID로 참조한다.
   같은 URL을 여러 파일에 복사하면 링크가 바뀔 때 한쪽만 고치게 된다.
4. **원문을 못 본 것은 못 봤다고 적는다.** 요약본만 읽고 원문을 읽은 척하지 않는다.
5. 남의 블로그 요약을 인용할 때는 **그 블로그가 아니라 원 연구를 찾아본다.**
6. **실무 주장은 누가 한 말인지 밝힌다.** "~해야 한다" ❌ / "OO는 ~라고 말한다" ⭕
7. **숫자에는 연도를 붙인다.** 국내 통계·플랫폼 수치는 해마다 바뀐다.

## 확인 절차

```
① 2차 자료로 개념 파악        → C
② 여러 2차 자료가 일치하는지    → B
③ 원문·공식 문서 URL 확보      → A
```

②에서 자료끼리 어긋나면 그 사실 자체를 적어둔다. 어느 쪽이 맞는지 모른 채
한쪽을 고르지 않는다.

## A·S 로 올리는 건 사람이 한다

③이 AI 작업만으로는 안 되는 경우가 많다. 이유와 역할 분담은 `작업환경.md`.


승급할 때는 그 원전이 든 `원전/레지스트리/*.yaml` 에서 이 세 개를 같이 고친다.

```
등급: A
원문확인: true
확인일: (실제로 연 날짜)
```

**확인 안 했는데 A로 올리지 않는다.** A는 "단정해도 된다"는 허가증이다.
허가증을 스스로 발급하면 이 등급 체계 전체가 장식이 된다.
