# 사이트 소유권 확인 - Search Console 도움말
# https://support.google.com/webmasters/answer/9008080?hl=ko

사이트 소유권 확인
소유권 확인이란 무엇인가요?

소유권 확인이란 특정 웹사이트의 소유자임을 Search Console에 증명하는 것을 의미합니다. 확인된 소유자는 Search Console에서 가장 높은 수준의 권한을 보유합니다.

소유권 확인 절차는 왜 이렇게 복잡할까요?
Search Console의 사이트 소유자는 사이트에 관한 민감한 Google 검색 정보에 액세스할 수 있으며, Google 검색 및 기타 Google 서비스에서 사이트의 존재와 행동에 영향을 미칠 수 있는 작업을 실행할 수도 있습니다. 따라서 Search Console에서는 실제 사이트 소유자에게만 소유자 권한이 부여되도록 하려고 합니다.
사이트 소유권 확인하기
새로운 속성을 추가하거나 속성 선택 도구에서 확인되지 않은 속성을 선택합니다.
아래에 표시된 확인 방법 중 하나를 선택한 다음 안내를 따릅니다. 사이트에 사용할 수 있으며 권장되는 방법이 확인 페이지에 표시됩니다.
어떤 이유로든 사이트 소유권을 확인할 수 없는 경우 현재 소유자에게 Search Console의 속성에 대한 액세스 권한을 부여해 달라고 요청하세요.

여러 확인 방법 사용

속성의 확인 설정 페이지에서 여러 가지 확인 방법을 추가할 수 있습니다. 기존 확인 방법 중 하나가 실패할 경우를 대비하여 확인 방법을 두 개 이상 추가하는 것이 좋습니다(예: 내가 Google 애널리틱스 추적 코드를 사용하여 확인했는데 다른 사람이 웹사이트의 템플릿을 변경하여 태그가 누락된 경우).

다른 확인 방법을 추가하려면 속성의 설정 페이지로 이동하여 소유권 확인을 클릭하세요.

여러 사용자가 서로 같거나 다른 확인 방법을 사용하여 동일한 웹사이트 속성의 소유권을 확인할 수 있습니다. 같은 확인 방법을 사용하는 경우 다른 소유자의 확인 토큰을 덮어쓰지 않도록 주의하세요.

하위 속성 확인하기

속성을 확인하면 추가한 모든 하위 속성이 상위 요소와 동일한 확인 방법을 사용하여 자동으로 확인됩니다. 즉, HTML 파일 업로드 방법을 사용하여 example.com의 소유권을 확인한 경우 생성한 모든 하위 속성(m.example.com 또는 https://example.com/some/path)이 동일한 HTML 파일 업로드를 통해 자동으로 확인됩니다.

확인은 얼마 동안 유지되나요?

Search Console에서 확인 토큰의 존재와 유효성을 확인할 수 있다면 소유권 확인은 계속 유지됩니다. Search Console에서는 확인 토큰이 계속 있고 유효한지 정기적으로 검사합니다. 소유권을 더 이상 확인할 수 없다면 알림이 전송됩니다. 문제가 해결되지 않으면 일정 유예 기간이 지난 후 해당 속성과 관련된 권한이 만료됩니다.

속성에 대해 모든 확인된 소유자가 액세스 권한을 상실하면 Search Console 속성에 대한 모든 사용자의 액세스 권한도 전부 사라집니다.

Google에서는 Google 사이트 인증 도구 사용자 에이전트를 사용하여 사이트 인증을 실행합니다.

언제부터 데이터를 볼 수 있나요?

속성에 관한 데이터는 소유권 확인이 진행되기 전이라도 누군가가 Search Console에 데이터를 추가하는 즉시 수집됩니다. 하지만 속성에 관한 데이터가 누적되려면 며칠 정도 걸릴 수 있습니다.

유일하게 확인된 사이트 소유자가 없어졌습니다.

사이트의 유일하게 확인된 소유자가 팀을 떠나면 본인이 소유권을 확인해야 속성에 계속 액세스하거나 액세스 권한을 다시 부여받을 수 있습니다.

다른 소유자의 사이트를 넘겨받는 경우 소유권을 확인한 후에 이전 소유자의 확인 토큰을 삭제하여 이전 소유자의 확인을 취소할 수 있습니다(예: HTML 태그가 확인된 소유자의 사이트에서 HTML 태그 삭제). 자세한 내용은 소유자 추가 또는 삭제를 참고하세요.

 

소유권 확인 방법 선택

Search Console에서는 여러 가지 확인 방법을 지원합니다. 아래 표에서 가장 적합한 방법을 선택하세요.

HTML 태그	비교적 간단하지만 사이트 홈페이지의 HTML 소스 코드를 수정할 수 있어야 합니다. 사이트 호스팅 플랫폼에서는 사용할 수 없는 경우도 있습니다.
Google 애널리틱스 추적 코드	이미 페이지에 내가 액세스할 수 있는 Google 애널리틱스 계정에 대한 Google 애널리틱스 추적 코드가 있다면 간단한 방법입니다. 페이지에 추적 코드가 없는 경우 추가해야 하며, 그렇게 하려면 Google 애널리틱스 계정이 없는 경우 만들어야 할 수 있습니다.
Google 태그 관리자	이미 페이지에 내가 액세스할 수 있는 Google 태그 관리자 계정에 대한 Google 태그 관리자 스니펫이 있다면 간단한 방법입니다. 페이지에 스니펫이 없는 경우 추가해야 하며, 그렇게 하려면 태그 관리자 계정이 없는 경우 만들어야 할 수 있습니다.

확인 태그는 어디에 넣어야 하나요?

태그 기반 확인 방법(Google 애널리틱스, Google 태그 관리자, HTML <meta> 태그 방법)을 사용하는 경우 Search Console에서 로그인하지 않은 사용자가 속성을 정의하는 URL을 방문할 때 리디렉션되는 페이지의 확인 태그를 찾습니다.

예

속성을 https://example.com으로 정의했으며 브라우저에 URL을 입력한 로그인하지 않은 사용자가 https://example.com/home으로 리디렉션되는 경우 Search Console에서 https://example.com/home 페이지의 확인 태그를 찾습니다.

파일 업로드 방법 등 다른 확인 방법의 경우 리디렉션을 따르지 않습니다.

일반적인 확인 문제

각 방법별 확인 오류 외에도 다음과 같은 확인 오류가 대부분의 확인 방법에서 발생할 수 있습니다.

잘못된 태그/스니펫/파일 오류
확인을 시작할 때 제공된 태그, 코드 스니펫, 파일을 그대로 사용해야 합니다.
서버와의 연결 시간이 초과되었습니다.
서버 시간 초과로 인해 파일을 확인할 수 없다면, 서버가 다운되었거나 작업량이 많아 응답이 느리기 때문일 가능성이 높습니다. 서버가 응답하는지 확인하고 다시 시도해 보세요.
사이트의 도메인 이름을 찾는 동안 오류가 발생했습니다.
확인 파일에 액세스하려고 했지만 DNS 오류 때문에 도메인에 액세스하지 못했습니다. 서버가 다운되었거나 DNS가 도메인에 연결하는 데 문제가 있기 때문일 수 있습니다. 도메인 이름이 정확하게 변환되는지 확인하고 다시 시도해 보세요.
다운로드 요청이 너무 많이 리디렉션되었습니다.
무한 루프와 같은 잠재적인 문제를 알아보려면 URL을 확인하세요.
서버가 잘못된 응답을 반환했습니다.
사이트에 비밀번호 인증이 필요하거나 다른 이유로 Google이 사이트에 액세스할 수 없는 경우 이 오류가 발생할 수 있습니다.
서버에 연결할 수 없습니다.
서버가 다운되지 않았는지, 도메인이 정확히 변환되는지 확인하고 다시 시도해 보세요.
내부 오류가 발생했습니다.
문제가 지속되면 검색 센터 도움말 포럼에서 업데이트를 확인하세요.
시간 초과
사이트 또는 도메인 서버가 Google의 요청에 응답하지 않습니다(사용된 확인 방법에 따라 다름). 사이트가 응답하는지 확인한 후 다시 시도하세요.
도메인을 찾을 수 없음
제공된 사이트 URL을 변환하려고 했지만 DNS 서비스에서 확인할 수 없습니다. 속성 URL을 정확히 입력했는지 확인하세요.
