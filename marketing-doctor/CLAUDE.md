> **하려는 일을 먼저 고르고, 그 줄에 적힌 파일만 본다.**
> 다른 폴더를 뒤지거나 인터넷을 먼저 찾지 않는다. 그러면 규칙이 섞인다.

## 지식창고는 폴더가 곧 성격이다

`지식/INDEX.md` 가 지식 목차, `지식/원전/INDEX.md` 가 출처 목차다.
폴더를 보면 **얼마나 믿어도 되는지**를 알 수 있다.

| 폴더 | 무엇이 | 쓸 때 |
|---|---|---|
| `지식/개념-손님/` `개념-값매기기/` `개념-가게키우기/` | 안 낡는 원리 · 해외 실증 연구 | 숫자가 아니라 **방향**을 옮긴다 |
| `지식/현황/` | 국내 조사 숫자 | **연도와 조사 대상**을 반드시 함께 쓴다 |
| `지식/플랫폼/네이버/` `메타/` `구글/` | 플랫폼 공식 문서 | **"~라고 밝힌다"** 로 인용한다 |
| `지식/AI검색/` | AI 답변에 인용되는 문제 | **가장 빨리 낡는다. 3개월마다** |
| `지식/홈페이지/` | 내 사이트 만들기·노출·보안·판매 | 네이버·구글 편은 **A**(전문 확보), 도구·보안 편은 B. **도구·요금 숫자는 안 옮긴다.** 반년 |
| `지식/법령/` | 법·고시·행정 절차 | **시행일을 같이 쓴다.** 전자상거래법·개인정보 보호법과 두 시행령·고시까지 **전부 A**(전문 확보) |
| `지식/판매경로/` | 위 전부를 손님 순서로 꿴 지도 | **새 사실을 만들지 않는다.** 포인터와 빈 자리만 |
| `지식/실무/` | 한 매장에서 해본 것 | **"해야 한다" 로 쓰지 않는다.** 표본 1개 |
| `지식/원전/레지스트리/` | 출처 레지스트리(`*.yaml`) | 서지·등급·URL. **출처는 여기 한 곳에만** |
| `지식/원전/확인기록/` | 무엇을 확인했고 **무엇을 못 했나** | 인용 전에 반드시 |
| `지식/원전/원문/` | 전문 확보한 원문 보관본 | **손대지 않는다** |
| `실전/` | 품목 레포에서 돌아온 **우리 데이터** | `워크플로우.md` 부터 본다. 지식창고와 **섞지 않는다** |
| `실전/양식/` | 품목 레포가 복사해 갈 계약 세 파일 | 모양을 바꾸면 분석이 깨진다 |
| `실전/품목/` | 받은 보고가 그대로 놓이는 자리 | **손대지 않는다.** 고칠 일은 품목 레포에서 |
| `실전/분석/` | 컨트롤 타워가 쓰는 분석 노트 | 제안까지만. 인과로 쓰지 않는다 |

`가이드/플랫폼/` 은 채널 세팅법(네이버 플레이스 등록 등)이다. 글쓰기와 별개.

## 네이버 규칙은 이미 창고에 있다 — 검색하지 않는다

네이버가 무엇을 빼는지·어떻게 줄 세우는지는 **공식 문서 전문을 확보해 뒀다.**
블로그 강의나 남의 글을 찾아보면 **2024년에 없어진 VIEW 탭 얘기**가 섞여 들어온다.

```
지식/플랫폼/네이버/네이버가-검색에서-빼는-글.md    무엇이 빠지나 (A등급·공식)
지식/플랫폼/네이버/네이버가-직접-부정한-것.md      저품질·지수는 네이버가 만든 말이 아니다
지식/플랫폼/네이버/네이버-검색로직.md             C-Rank · D.I.A. (A등급·공식)
지식/플랫폼/네이버/네이버-어디에-걸리나.md         스마트블록 · AI브리핑
지식/원전/원문/네이버/ · 네이버-사이트/     네이버 공식 문서 전문 20건 (손대지 않음)
```

**가게(플레이스·광고)는 블로그와 다른 문서다.** 섞지 않는다.

```
지식/플랫폼/네이버/네이버-플레이스-순위.md         순위 요소 · 사진 규칙 · AI 이미지 (A등급·공식)
지식/플랫폼/네이버/네이버-광고는-이렇게-과금된다.md  '길찾기' 만 눌러도 과금
```

**창고에 없는 것만 새로 조사한다.** 조사했으면 반드시 창고에 넣는다.

## 지금 안 쓰는 것 (지우지 않고 보관 중)

점수·감점 방식의 **글 진단기는 중단됐다.** 방향이 "알려주는 블로그" 로 바뀌었다.

```
기준/진단기준.yaml · 기준/업종팩.yaml · 기준/입력항목.yaml
엔진/scorer.py · 엔진/guide_status.py · 엔진/preview_build.py
가이드/진단/ · 콘텐츠/블로그_글목록.md 의 '진단 항목' 열
```

**여기서 규칙을 가져오지 않는다.** 글쓰기 규칙은 `콘텐츠/전달규칙.md` 하나뿐이다.
(다만 진단기 항목에 담긴 판단은 지식 파일로 옮겨져 있다. 예: 경험 없는 글 → `네이버가-검색에서-빼는-글.md`)

## 이 레포가 뭐 하는 곳인가 — 컨트롤 타워

**장사하시는 사장님께 마케팅을 알려주는 블로그**를 위한 지식창고이자,
품목 레포들이 가져다 쓰는 **판단 기준의 원본**이다.

```
여기 (marketing-doctor)          품목-○○ (레포를 따로 판다)
· 지식을 모으고 갱신한다          · 스킬을 복사해 간다
· 스킬을 만들어 내보낸다  ────▶   · 실제로 글 쓰고 팔고 광고한다
· 실전 기록을 받아 쌓는다  ◀────   · 주간 기록을 되돌려 보낸다
```

**실험은 품목 레포에서, 보존과 학습은 여기서.**
품목이 늘어도 판단 기준은 한 곳이어야 한다 — 갈라지면 같은 실수를 두 번 한다.

**스킬을 품목 레포에서 고치지 않는다.** 여기서 고치고 다시 복사해 간다.

글을 대신 써주는 곳도, 점수를 매기는 곳도 아니다.

## 절대 규칙 넷

1. **출처 없는 숫자를 쓰지 않는다.** 등급과 인용법은 `지식/출처등급.md`.
   널리 도는 통계라도 **원문과 대조한 기록**이 창고에 없으면 쓰지 않는다.

   ★ 이건 사장님이 직접 못 박은 규칙이다(2026-09-01).
   ```
   ⭕ 쓸 수 있는 것   동료심사 학술지 · 플랫폼 공식 문서 · 정부·공공 조사
                      + 그 서지정보(저자·연도·학술지·표본)를 같이 적을 수 있을 때
   ❌ 쓸 수 없는 것   검색 결과 요약문을 원문으로 취급하는 것
                      대행사·SEO 블로그가 "OO에 따르면" 하고 든 숫자
                      원 조사를 특정하지 못한 채 도는 통계
                      내가 그럴듯하게 추론해서 만든 문장
   ```
   **모르면 "못 찾았다" 고 적는다.** 그게 이 창고의 값어치다.
   내가 두 자료를 붙여 만든 해석은 **"우리가 붙인 것" 이라고 반드시 밝힌다.**
   조사 순서와 뚫리는 경로는 `지식/작업환경.md`.

2. **매장 이름·지역·전화번호가 들어가면 안 된다.** 커밋 전 `엔진/brand_check.py`.
3. **같은 규칙을 두 파일에 쓰지 않는다.** 누락의 가장 큰 원인이다
   (`기준/파일정리규칙.md`).
4. **삭제는 제안만 하고 승인받는다.** 자동으로 지우지 않는다.

## 내보내는 스킬 (품목 레포가 복사해 간다)

```
.claude/skills/naver-blog/        블로그 운영 — 글감·글쓰기·점검·안 보일 때
.claude/skills/product-launch/    품목 내놓기 — 자리 0 · 12주 · 주간 기록 · 가짜 숫자
```

**둘 다 존댓말이고 사장님이 직접 읽는다.** 창고 파일(평서체)과 성격이 다르다 —
같은 내용을 옮기는 게 아니라 **실행 순서로 바꿔 쓴 것**이다.

## 새 파일을 만들면

`기준/파일정리규칙.md` 의 크기 상한을 지키고, **이 파일의 표에 등록한다.**
표에 없는 폴더가 생기면 `엔진/file_audit.py` 가 잡는다.
