# 파일 정리 규칙 — 누락 방지

> 파일이 커지면 읽다가 빠뜨린다. 규칙이 흩어지면 한쪽만 고치고 다른 쪽이 남는다.
> 이 둘이 누락의 두 가지 원인이다. 아래 규칙은 그것만 막는다.
> 검수: `python3 엔진/file_audit.py`

---

## 1. 크기 상한

파일의 **성격에 따라** 상한이 다르다. 항상 로드되는 파일이 제일 엄격하다.

| 성격 | 예 | 글자 | 줄 | 왜 |
|---|---|---:|---:|---|
| **항상 로드** | `SKILL.md` `CLAUDE.md` `AGENTS.md` `README.md` | 8,000 | 250 | 켜질 때마다 통째로 들어간다. 길수록 매번 비싸다 |
| **필요할 때 읽음** | `가이드/**` `references/**` | 6,000 | 200 | 한 번에 읽고 다 반영할 수 있는 분량 |
| **기계가 읽음** | `기준/**.yaml` | 10,000 | 350 | 사람도 훑어야 하므로 무한정 키우지 않는다 |
| **코드** | `엔진/*.py` | 12,000 | 400 | 한 번에 읽히는 분량. 300줄은 실무에서 큰 파일이 아니다 |

넘으면 **쪼갠다.** 줄이려고 내용을 지우지 않는다.

## 2. 폴더 상한

- 한 폴더에 **파일 15개**까지. 넘으면 하위 폴더로 나눈다.
- 깊이는 **3단계**까지. `기준/항목/A-저품질위험.yaml` 정도.

## 3. 한 파일 = 한 주제

- 파일 이름만 보고 안에 뭐가 있는지 알 수 있어야 한다.
- 성격이 다른 둘을 한 파일에 담지 않는다. (규칙 + 예시 + 코드 → 세 파일)

## 4. 규칙은 한 곳에만 ★

**같은 규칙을 두 파일에 쓰지 않는다.** 이게 누락의 가장 큰 원인이다.
한쪽만 고치면 다른 쪽에 옛 규칙이 남고, 나중에 어느 쪽이 맞는지 아무도 모른다.

- 진단 항목의 정의는 `기준/항목/` 에만.
- 다른 문서는 **항목 ID로 참조**한다. 내용을 복사하지 않는다.
- 배포용 사본(`assets/`)처럼 복사가 불가피하면 **검수기가 동기화를 확인**한다.

## 5. 파일 맨 위에 무엇을 담는지 쓴다

첫 5줄 안에 한 줄이라도 있어야 한다.

```markdown
# 제목
> 이 파일이 담는 것. 그리고 담지 않는 것.
```

## 6. 쪼갤 때

1. 원본을 성격대로 나눈다
2. **인덱스에 새 파일을 등록한다** — 등록하지 않으면 잊힌다
3. 원본을 지우기 전에 **내용이 전부 옮겨졌는지 확인**한다
4. 참조하던 곳의 경로를 고친다

## 7. 인덱스

`INDEX.md` 가 폴더의 목차다. 모든 파일이 여기 있어야 한다.
- 인덱스에 없는 파일 = **고아 파일**. 아무도 안 읽는다.
- 인덱스에 있는데 없는 파일 = **죽은 링크**.

둘 다 검수기가 잡는다.

---

## 검수 체크리스트

파일을 추가·수정·분할한 뒤 `python3 엔진/file_audit.py` 를 돌린다.
아래를 자동으로 본다.

- [ ] 크기 상한을 넘은 파일이 없다
- [ ] 한 폴더에 파일이 15개를 넘지 않는다
- [ ] 인덱스에 없는 파일(고아)이 없다
- [ ] 인덱스에 적혔는데 실제로 없는 파일이 없다
- [ ] 깨진 상대 링크가 없다
- [ ] 진단 항목 ID가 두 곳 이상에 정의돼 있지 않다
- [ ] 기준표의 모든 항목이 어딘가에서 쓰이고 있다
- [ ] 파일 맨 위에 무엇을 담는지 적혀 있다
- [ ] 배포용 사본이 원본과 같다

사람이 눈으로 볼 것 (자동으로 못 잡음)

- [ ] 쪼갠 뒤 원본 내용이 **하나도 빠지지 않았다**
- [ ] 옮긴 내용이 새 파일의 주제와 맞다

## 참고 블록은 임시 자리다

`진단기준.yaml` 의 `참고:` 는 **가이드를 아직 안 쓴 항목의 임시 보관함**이다.
가이드를 쓰면 그 내용을 가이드로 옮기고 `참고:` 는 지운다.

안 그러면 같은 설명이 두 곳에 남는다(규칙 4 위반). 그리고 둘이 서로 달라진다.
`진단기준.yaml` 이 줄 상한에 자꾸 부딪히면 대개 이게 원인이다.
상한을 늘리기 전에 **가이드로 옮길 게 없는지부터** 본다.
