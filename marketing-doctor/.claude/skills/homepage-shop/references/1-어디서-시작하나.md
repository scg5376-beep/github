# 어디서 시작하나

> ⚠️ **B등급입니다.** KRNIC·KISA·ICANN·GitHub·Vercel 페이지가 전부 막혀
> **원문을 못 열었습니다.** 발췌와 2차 자료를 대조했을 뿐입니다.
> 그래서 이 파일에는 **큰따옴표를 쓰지 않았습니다.** 요금·기간·서류도 안 적었습니다.

## 1. 도메인은 사는 게 아니라 빌리는 것입니다

KRNIC 안내에 따르면 .kr/.한국 도메인 등록은 수수료를 내고 **일정 기간 보유**하는
것입니다. **만료되면 남이 가져갑니다.**

| 종류 | 누가 관리 | 어디서 등록 |
|---|---|---|
| .kr / .co.kr / 한글.kr | 한국인터넷진흥원 (인터넷주소자원법) | 진흥원이 아니라 **등록대행자** |
| .com / .net / .shop 등 | ICANN 체계 | ICANN 인가 등록기관 |

- 등록대행자를 **바꿀 때 수수료는 없고**, 사용기간을 1년 연장해야 한다고 전해집니다.
- .com 계열은 **등록자 이름·조직·이메일을 바꾸면 60일간** 다른 등록기관으로 못
  옮긴다고 전해집니다(도메인 탈취 방지).
- 누가 먼저 잡았나 다툼은 **인터넷주소분쟁조정위원회**에 조정을 신청할 수 있다고
  전해집니다.

**상호와 도메인은 별개입니다.** 도메인을 잡았다고 상표권이 생기지 않습니다.
상표는 특허청 문제입니다. *(이건 우리가 붙인 것입니다.)*

⚠️ **.kr 과 .com 중 무엇이 검색에 유리한가** — 근거 있는 자료를 못 찾았습니다.
**아무 말도 하지 않습니다.**

### ★ 싸게 나온 도메인은 과거를 확인하십시오

네이버 「웹 콘텐츠 스팸사례」 원문입니다. **여기만 A등급입니다.**

> 과거에 공신력 있는 기관이나 단체가 사용하던 만료 도메인을 구매한 뒤, 기존 신뢰도를 이용해 검색 순위를 높일 목적으로 스팸·유해 콘텐츠를 게시하는 경우입니다. 예를 들어 공공기관이나 학교와 같은 시설에서 사용하던 도메인에 관련 없는 콘텐츠를 게재하는 방식이 해당됩니다.

싸게 나온 데는 이유가 있을 수 있습니다.

## 2. 어디에 올리나 — 셋 중 하나입니다

*(이 분류는 공식 출처가 아니라 고르실 때 헷갈리지 않게 우리가 나눈 것입니다.)*

```
① 빌더        클릭으로 만들고 월 요금. 결제·상품 기능이 들어 있습니다
② 오픈마켓     홈페이지가 아니라 남의 장터에 입점합니다 → 4-온라인으로-팔려면.md
③ 직접 구축    개발자나 AI 로 코드를 만들어 호스팅에 올립니다
```

- **네이버 modoo!(모두) 는 2025-06-26 에 끝났습니다.** 독립 출처 넷이 같은 날짜입니다.
- **빌더 요금은 자주 바뀝니다. 숫자를 옮기지 않습니다.** 요금 페이지를 직접 보십시오.
- **도구 비교·추천은 이 스킬에 없습니다.** 반년이면 다 바뀝니다.

### ★ 공짜 호스팅은 장사에 못 씁니다 — 약관이 막습니다

③을 고르면 흔히 듣는 말이 어떤 곳은 공짜라는 것입니다. **약관이 막습니다.**

| 서비스 | 약관 취지 (전해집니다) |
|---|---|
| GitHub Pages | 온라인 비즈니스·이커머스 등 **상거래 목적의 무료 호스팅으로 쓸 수 없음** |
| Vercel Hobby | **비상업적 개인 용도**로 제한. 상업 사용은 유료 플랜 |

**가게 홈페이지는 상업 사용입니다.** 공짜 플랜에 올렸다가 내려가면 손님이 못 들어옵니다.

## 3. AI 로 만들 때 — 되는 것과 사람이 봐야 하는 것

**바이브 코딩**이라는 말은 2025-02 에 붙었습니다. 코드가 있다는 걸 잊고 AI 에게
말로 시키는 방식입니다. **그런데 같은 사람이 2026-04 에 그 시기는 지났다고 말한
것으로 전해집니다** — 사람이 명세를 쓰고 계획을 감독하고 결과를 검토하는 쪽으로요.

**사장님께 필요한 건 둘 다입니다.** 만들 수 있다는 것과, 사람이 확인한다는 것.
어느 한쪽만 들으면 틀립니다.

### 실증이 가리키는 자리 넷

| 무엇을 봤나 | 결과 (전해집니다) |
|---|---|
| AI 어시스턴트를 쓴 사람 vs 안 쓴 사람 (동료심사) | 쓴 쪽이 **덜 안전한 코드**를 썼고 **더 안전하다고 믿었습니다** |
| LLM 100여 개가 만든 코드 (보안 판매사 보고서) | 절반 가까이에 보안 결함. 새 모델이라고 낫지 않았습니다 |
| 어느 AI 빌더로 만든 앱 1,600여 개 | 10% 남짓이 **DB 접근 제한이 없어** 이름·전화·주소가 읽혔습니다 |
| 어느 에이전트 사고 (표본 1) | 코드 동결 중에 운영 DB 를 삭제했습니다 |

★ 넷이 같은 방향입니다. **만들어지는 것과 안전한 것은 다릅니다.**
그리고 첫 번째 연구의 핵심은 **만든 사람이 위험을 못 느낀다**는 것입니다 —
사장님이 "잘 돌아가는데?" 라고 느끼는 바로 그 상태입니다.

⚠️ **"AI 로 만들면 위험하다" 로 읽지 마십시오.** 근거는 **"사람이 확인할 자리가
있다"** 까지입니다.

### 그래서 이렇게 확인합니다

```
손님 정보를 받는가   →  받으면 개인정보보호법이 걸립니다 (3-지켜야-할-것.md)
DB 를 쓰는가         →  ★ "로그인 안 한 사람이 남의 데이터를 볼 수 있나" 를 반드시 물어봅니다
결제가 있는가        →  직접 만들지 말고 PG·빌더·오픈마켓에 맡깁니다
                        (통신판매업 신고 서류도 거기서 나옵니다)
백업이 있는가        →  되돌릴 수 있는지 먼저 확인합니다
검색에 보이는가      →  2-검색에-보이게-하려면.md
어디에 올리나        →  공짜 플랜은 상업 사용 금지 (위 2절)
```
