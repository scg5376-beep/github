# 빠르고 안전하게

> **등급이 섞여 있습니다.** 속도 지표의 정의·기준값과 네이버 스팸 사례는 **A**,
> 순위 영향·속도매출 조사·보안 도구 쪽은 **B** 입니다. 절마다 표시했습니다.
> 법 쪽(개인정보)은 product-launch 스킬의 `0-팔-수-있는-상태인가.md` 에 있습니다.

## 1. 구글이 재는 것 셋  **A등급**

> 최대 콘텐츠 페인트 (LCP): 로드 성능을 측정합니다. 좋은 사용자 경험을 제공하려면 페이지 로드가 시작된 후 2.5초 이내에 LCP가 발생해야 합니다.

> 다음 페인트에 대한 상호작용 (INP): 상호작용성을 측정합니다. 좋은 사용자 경험을 제공하려면 페이지의 INP가 200밀리초 이하여야 합니다.

> 누적 레이아웃 이동 (CLS): 시각적 안정성을 측정합니다. 좋은 사용자 경험을 제공하려면 페이지의 CLS가 0.1 이하로 유지되어야 합니다.

**기준값을 외울 필요는 없습니다.** 도구가 알려 줍니다. 중요한 건 **무엇을 재는지**입니다 —
얼마나 빨리 보이나 · 눌렀을 때 반응하나 · 화면이 흔들리나.

⚠️ 한국어판은 **기계 번역**입니다. 구글이 그렇게 고지했고, 실제로 용어가 어긋난 곳이
있습니다. 인용할 때 그 사실을 밝히십시오.

### 판정은 내 컴퓨터가 아니라 손님들 기준입니다  **A등급**

> 대부분의 사용자를 대상으로 이러한 측정항목의 권장 목표치를 달성하려면 모바일 및 데스크톱 기기별로 구분하여 페이지 로드 횟수의 75번째 백분위수를 측정 기준으로 삼는 것이 좋습니다.

**셋 다 통과해야 하고, 모바일과 데스크톱을 따로 봅니다.**

> 실험실 측정은 우수한 환경을 제공하는 데 필수적이지만, 현장 측정을 대체할 수는 없습니다.

```
현장(필드)   PageSpeed Insights · Search Console   ← 진짜 손님들 숫자
실험실       DevTools · Lighthouse                 ← INP 는 못 잽니다
```

### ★ 기준은 바뀝니다 — 그게 문서에 적혀 있습니다  **A등급**

> 핵심 사항: 안정적인 측정항목이 반드시 영구적인 것은 아닙니다. […] 2024년에 INP가 안정적인 Core Web Vital 측정항목이 되면서 FID에 정확히 동일한 일이 일어났습니다.

**실제로 지표 하나가 교체됐습니다.** "3대 지표" 를 외워 두면 언젠가 틀린 지식이 됩니다.

### 순위에는 얼마나  **B등급**

```
"속도만 올리면 순위가 오른다"   →  구글 문서가 부정합니다. 관련성이 먼저입니다
"속도는 순위와 무관하다"        →  이것도 부정합니다. 순위 시스템이 씁니다
```

구글 문서가 밝힌 것은 넷입니다 — 순위 시스템이 **사용하고**, **단일 신호는 없고**,
점수가 좋다고 **상위 노출이 보장되지 않고**, 나머지 페이지 경험 요소는 순위를
**직접 올리지 않습니다.**

### 손님 쪽 숫자는 연도를 반드시 붙이십시오  **B등급**

```
2016년 구글 조사    3초 넘으면 모바일 방문 절반 넘게 이탈   ← 10년 전 네트워크입니다
2020년 딜로이트     0.1초 개선 ↔ 리테일 전환 상승          ← 구글 의뢰 · 상관관계 · 대형 브랜드
2024년 웹 알마낙    모바일 통과율 절반이 안 됩니다          ← 전 세계 사이트
```

**세 조사 모두 동네 가게 사이트를 잰 게 아닙니다.** 방향(느리면 나간다)만 옮기십시오.

⚠️ **"100ms 마다 매출 1% 를 잃는다"** 는 유명한 숫자는 **쓰지 마십시오.**
2006년 강연 슬라이드가 출처이고 공식으로 낸 적이 없습니다.

### 실제로 손댈 수 있는 것 *(우리가 붙인 것입니다)*

```
LCP   첫 화면의 큰 사진 하나가 범인인 경우가 많습니다. 사진 용량을 줄입니다
CLS   나중에 뜨는 배너·팝업이 화면을 밀어냅니다. 자리를 미리 잡거나 뺍니다
INP   빌더 앱·위젯을 많이 붙이면 느려집니다. 안 쓰는 걸 뺍니다
측정   PageSpeed Insights (pagespeed.web.dev)
```

## 2. HTTPS 는 이제 선택이 아닙니다  **B등급**

| 언제 | 무엇 (전해집니다) |
|---|---|
| 2018-07 | HTTP 사이트 주소창에 **Not secure** 표시 |
| **2026-10** | **항상 보안 연결 사용이 기본.** 공개 사이트에 HTTPS 가 없으면 첫 접속 전에 **사용자에게 허락을 묻습니다** |

**HTTP 홈페이지는 손님이 경고창을 넘어야 들어옵니다.**

- 인증서는 무료로 받을 수 있습니다. 유효기간이 **점점 짧아집니다** — 지금 90일에서
  단계적으로 45일까지 줄어드는 일정이 공지돼 있다고 전해집니다.
  **수동으로 갱신하는 사이트는 앞으로 반드시 끊깁니다.** 빌더를 쓰면 빌더가 합니다.
- **HTTPS 는 법 준수이기도 합니다.** 개인정보 안전성 확보조치 고시가 전송 암호화를
  요구합니다. **문의 폼이 HTTP 면 그걸 안 한 것입니다.**

## 3. ★ 방치하면 남이 내 사이트를 씁니다  **A등급**

네이버 「웹 콘텐츠 스팸사례」 원문입니다.

> 정상 운영 사이트의 보안 취약점을 공략해 스팸 사이트로 이동하는 링크를 페이지 내에 대량 삽입하거나, 링크만으로 구성된 페이지를 생성해 노출을 시도하는 경우입니다. 관리가 소홀한 경로나 게시판이 주요 표적이 되며, 이로 인해 사이트 전체가 불이익을 받을 수 있습니다. 누구나 작성할 수 있는 게시판의 경우 회원제로 운영하여 정상적인 인증 절차로 유지하거나, 최소한의 방어 장치를 마련하는 것을 권장합니다.

★ **해킹은 사장님이 모르는 채로 진행됩니다.** 특정 접속에서만 스팸이 보이도록
설계되면 사람 눈에는 멀쩡합니다. 그래서 검색로봇이 받는 HTML 을 봐야 합니다.

> 내 사이트가 해킹되었는지 확인하려면 서치어드바이저 [웹마스터 도구 > 검증 > URL 검사]를 통해 실제 검색로봇에 수집되는 HTML을 점검해보세요. 피해 사실을 인지한 후 신속하게 보안 조치 및 콘텐츠 제거 등 합리적 조치를 취한 경우에는, [검색 노출 제보하기] 를 통해 검색 노출 정상화를 요청할 수 있습니다.

**당한 뒤에 되돌리는 길이 열려 있습니다.**

> 본 정책에 따른 검색 노출 제한 조치에 대하여 이의가 있거나, 보안 조치 등 시정 조치를 완료한 사이트 운영자는 검색 노출 정상화를 요청할 수 있습니다.
