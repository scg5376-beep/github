# 2단계 · 종류별 처방

> 진단에서 나온 항목마다 **무엇을 하는지**가 다르다.
> 여기 적힌 건 전부 **실제로 겪고 고친** 모양이다.

## 깨진 링크

```
1  가리키는 파일이 어디로 갔는지 찾는다 (이름으로 검색)
2  옮겨진 거면 링크를 고친다
3  없어진 거면 → 그 링크를 왜 걸었는지 본다.
   내용이 아직 필요하면 만들고, 아니면 링크를 지운다
```

**아직 안 만든 자산(스크린샷 등)을 가리키는 링크는 오류가 아니다.**
다만 "아직 없다" 고 그 자리에 적어 둔다. 안 그러면 다음 사람이 또 찾는다.

## ★ 한 파일에 같은 절이 두 번 — 제일 먼저 고친다

**둘 중 하나는 낡은 판이다.** 그런데 사람은 위엣것을 본다.

```
1  두 절을 나란히 놓고 다른 점을 적는다
2  어느 쪽이 최신인지 근거로 정한다 (날짜 · 커밋 · 다른 문서와의 일치)
3  낡은 판을 지운다 — 지우기 전에 사람에게 확인받는다
4  왜 두 벌이 생겼는지 한 줄 적어 둔다. 같은 일이 또 생긴다
```

**"둘 다 남기고 나중에 정하자" 가 가장 나쁘다.** 그 사이에 누가 낡은 걸 보고 일한다.

## 크기 초과

**상한을 올리지 않는다. 성격으로 나눈다.**

```
❌ 상한을 6,000 → 12,000 으로 올린다        길이가 문제가 아니라 성격이 섞인 것이다
⭕ 성격이 다른 절을 새 파일로 뺀다
⭕ 그 성격이 여럿이면 성격을 하나 만든다 (예: 보관본은 고치지 않으니 상한이 달라도 된다)
```

**나눌 때는 목차 파일에 한 줄을 같이 넣는다.** 안 넣으면 그 파일은 그날부터 고아다.

## 폴더 과밀 (15개 넘음)

```
1  그 폴더 안 파일을 성격으로 묶어 본다
2  묶음이 보이면 하위 폴더를 만든다
3  깊이가 이미 상한이면 하위 대신 **형제 폴더**로 가른다
```

**실제 예** — 보관 폴더가 16칸이 됐는데 이미 최대 깊이라 하위를 못 팠다.
그래서 성격 둘(`○○-거래/` · `○○-개인정보/`)로 갈랐고,
**참조 열넷을 같이 고쳤다.** 가르기 전에 `grep -rn` 으로 참조를 먼저 센다.

## 같은 제목이 여러 파일에 (참고)

**나란한 문서들이 같은 틀을 쓰는 건 정상이다.** (`고치는 방법` 이 열 파일에 있는 식)

문제는 **같은 규칙이 두 곳에 적힌 것**이다. 이건 제목만으로는 안 보이니 본문을 본다.

```
규칙은 한 곳에만 둔다. 다른 곳에서는 가리키기만 한다.
두 곳에 적으면 한 곳만 고치게 되고, 그때부터 어느 게 맞는지 모른다.
```

## 아무도 안 가리키는 파일 (참고)

```
· 폴더 단위로 가리켜지는 곳(보관본·자산)은 정상이다
· 템플릿·설치 안내는 사람이 직접 여는 파일이라 정상일 수 있다
· 나머지는 둘 중 하나다 — 목차에서 빠졌거나, 죽은 파일이거나
```

**죽은 파일이라고 바로 지우지 않는다.** "지금 안 쓰는 것" 자리로 옮기고
**왜 안 쓰는지**를 적는다. 나중에 되살릴 근거가 된다.

## 뒤처진 문서 (참고)

**오래된 게 틀린 건 아니다.** 원문이 2016년 문서면 2016이 맞다.

봐야 할 건 **"이 문서가 언제까지 유효한가" 가 적혀 있느냐**다.

```
⭕ 문서 맨 위에  확인일 / 다시 볼 날 / 무엇이 바뀌면 다시 보나
❌ 날짜가 아예 없다  → 낡았는지 아무도 모른다
```
