# 3단계 · 구조를 정한다

> **폴더가 곧 성격이다.** 이 한 줄이 정리의 전부다.
> 폴더를 보고 "이건 얼마나 믿어도 되나 · 얼마나 자주 낡나" 를 알 수 있어야 한다.

## 성격으로 가른다 — 주제로 가르지 않는다

```
❌ 주제로 가르기    A제품/ B제품/ C제품/     → 같은 종류의 규칙이 세 곳에 생긴다
⭕ 성격으로 가르기  기준/ 자료/ 기록/ 보관/   → 규칙은 한 곳, 자료는 한 곳
```

**성격을 가르는 질문 셋**

```
1  얼마나 자주 낡나          매일 · 반년 · 안 낡음
2  고치는 것인가 두는 것인가   우리 글 vs 남의 문서 보관본
3  누가 읽나                 사람이 직접 · 도구가 읽음 · 항상 로드됨
```

## 크기 상한은 성격마다 다르다

| 성격 | 글자 | 줄 | 왜 |
|---|---:|---:|---|
| 항상 로드 (`CLAUDE.md` `README.md` `SKILL.md`) | 8,000 | 250 | 켜질 때마다 통째로 들어간다 |
| 사람이 읽는 글 | 6,000 | 200 | 한 번에 읽고 다 반영할 수 있는 분량 |
| 도구가 읽는 설정 | 10,000 | 350 | 사람도 훑어야 하니 무한정 키우지 않는다 |
| 코드 | 12,000 | 400 | 한 번에 읽히는 분량 |
| **보관본 · 로그** | 크게 | 크게 | **고치지 않는 것**이라 빠뜨릴 위험이 없다 |

**상한은 절대 올리지 않는다.** 부딪히면 성격으로 나눈다.
상한을 올려서 해결한 자리는 반드시 나중에 다시 부딪힌다.

## 폴더 상한과 깊이

```
한 폴더에 파일 15개까지    넘으면 하위 폴더로 나눈다
깊이는 4단계까지          이미 4단계면 하위 대신 형제 폴더로 가른다
13칸이 되면 재편을 예약한다  15에서 부딪히면 급해지고, 급하면 참조를 놓친다
```

## 목차와 라우팅 표 — 둘 다 필요하다

**목차(INDEX)** 는 "여기 뭐가 있나" 다. 폴더마다 하나.
**라우팅 표** 는 "이 일을 할 때 어느 파일을 보나" 다. 레포에 하나.

라우팅 표가 없으면 **다음 사람이 폴더를 뒤진다.** 뒤지면 규칙이 섞이고 빠진다.

```
| 하려는 일 | 이 순서로 본다 | 절대 안 보는 것 |
|---|---|---|
| ○○ 할 때 | ① □□.md ② △△.md | 낡은 폴더 |
```

★ **'절대 안 보는 것' 칸이 실제로 제일 값어치 있다.**
안 볼 곳을 못 박아야 낡은 자료가 다시 안 섞인다.

## 규칙은 한 곳에만

```
같은 규칙을 두 파일에 쓰지 않는다.
두 곳에 적으면 한 곳만 고치게 되고, 그때부터 어느 게 맞는지 모른다.
```

**이게 누락의 가장 큰 원인이다.** 두 번째 자리에는 규칙 대신 **가리키는 한 줄**만 둔다.

## 지우지 않고 보관하는 자리를 만든다

**안 쓰게 된 것을 바로 지우지 않는다.** "지금 안 쓰는 것" 자리를 만들고
**왜 안 쓰는지 · 어디로 대체됐는지**를 적는다.

```
지금 안 쓰는 것 (지우지 않고 보관 중)
  □□.yaml · △△.py       ○○ 방식이 중단됐다. 대체: ▽▽.md
  여기서 규칙을 가져오지 않는다
```

**"여기서 가져오지 않는다" 를 반드시 적는다.** 안 적으면 다음 사람이 가져다 쓴다.
