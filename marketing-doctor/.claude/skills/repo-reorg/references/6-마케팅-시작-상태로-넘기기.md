# 6단계 · 정리의 끝은 "팔 준비가 된 상태" 다

> **정리가 목적이 아니다.** 이 레포에서 실제로 마케팅을 돌리는 게 목적이다.
> 그래서 마지막 단계는 "깔끔해졌다" 가 아니라 **"내일 시작할 수 있다"** 여야 한다.

## 정리가 끝났는지 보는 기준

```
□ 진단의 '고칠 것' 이 0 이거나, 남은 것마다 "왜 두는지 · 언제 다시 보는지" 가 적혀 있다
□ 라우팅 표만 보고 다음 사람이 어디를 볼지 안다
□ 낡은 판이 남아 있지 않다 (같은 절 두 번 · 서로 어긋나는 값)
□ 안 쓰는 것은 지워지지 않고 "왜 안 쓰는지" 와 함께 보관 자리에 있다
□ 검사기가 심겨 있고, 사람이 잊어도 도는 자리(워크플로)에 걸려 있다
```

★ **첫 줄을 "0 건" 으로만 적어 뒀다가 고쳤다** (2026-09-03). 실제 레포는 204 건에서
시작해 54 건에서 멈췄는데, 남은 54 건은 **정리 범위 밖(코드 리팩터링)이거나 성격상
정상(템플릿·대장)이거나 미룬 것(폴더 나누기)** 이었다. 0 을 만들려고 억지로 줄이면
규칙이 샌다. **끝은 숫자가 아니라 "남은 것에 전부 이유가 붙어 있는 상태" 다.**

그래서 이 도구의 `허용초과` 는 크기뿐 아니라 어떤 항목이든 받는다 —
`"종류": "같은 절"` 처럼 적고 **왜 · 다시볼날 · 그때볼것**을 붙인다.

**여기까지는 준비다.** 아래가 실제 시작이다.

## 마케팅을 돌리려면 세 가지가 더 있어야 한다

### ① 자리 0 이 닫혀 있다

팔기 전에 닫아야 하는 법적 절차다. **안 닫고 광고를 돌리면 쓴 돈이 전부 샌다.**

```
□ 사업자등록 · 통신판매업 신고(또는 면제 확인)
□ 사이버몰 표시 여섯 가지
□ 광고 표시 세 가지 (신고번호는 여기다)
□ 청약철회 안내 · 주문 내역 서면
□ 개인정보 처리방침을 홈페이지에 게재
```

→ `product-launch` 스킬의 `references/0-팔-수-있는-상태인가.md` 에 근거와 함께 있다.

### ② 보고/ 계약 폴더가 서 있다

기록할 자리가 없으면 12주 뒤에도 느낌으로 판단하게 된다.

```
보고/품목.yaml   시작할 때 한 번. 자리 0 체크 · 판단지표 · 안 하기로 한 것
보고/주간.csv    한 주 한 줄. 헤더 고정
보고/기록.md     무엇을 왜 바꿨나
```

**이름과 모양을 바꾸지 않는다.** 바꾸면 컨트롤 타워가 분석을 못 한다.

### ③ 스킬이 들어와 있다

```
.claude/skills/product-launch/    품목 내놓기 — 자리 0 · 12주 · 주간 기록
.claude/skills/naver-blog/        블로그를 같이 할 거면
```

**컨트롤 타워에서 복사해 온다.** 여기서 고치지 않는다 —
고칠 게 생기면 컨트롤 타워에서 고치고 다시 복사한다.

## 정리와 마케팅을 같은 커밋에 섞지 않는다

```
1  구조 개편 커밋들          (여기까지가 이 스킬)
2  자리 0 닫기 커밋
3  보고/ 세우기 커밋
4  스킬 복사 커밋
5  ── 여기부터 실전. 주간 기록이 쌓이기 시작한다
```

**섞으면 나중에 "이 숫자가 언제부터의 것인가" 를 못 정한다.**
1~4 를 끝낸 커밋에 태그나 표시를 남겨 두면 그게 기준선이 된다.

## 기존에 쌓여 있던 것은 어떻게 하나

대량 세션이 만들어져 있던 레포라면 **과거 기록이 이미 있을 수 있다.**

```
살린다   실제로 무엇을 했고 무엇이 있었는지 — 날짜가 붙어 있는 것
         → 보고/기록.md 맨 앞에 "정리 전 기록" 으로 옮긴다
안 살린다  세션 로그 · 중간 산출물 · 어느 판이 맞는지 모르는 것
         → 지우지 말고 보관 자리로. "왜 안 쓰는지" 를 적는다
```

⚠️ **과거 숫자를 주간.csv 에 소급해 채우지 않는다.**
그때 무엇을 어떻게 셌는지 모르면 그 숫자는 나중에 착시만 만든다.
**빈칸으로 두고, 기록.md 에 "이 시점 이전은 안 셌다" 고 적는다.**
