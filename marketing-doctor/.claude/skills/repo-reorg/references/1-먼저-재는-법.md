# 1단계 · 먼저 잰다 (아직 아무것도 고치지 않는다)

> **정리를 감으로 시작하면 반드시 뭔가를 잃는다.**
> 무엇이 얼마나 문제인지 숫자로 본 다음에 손을 댄다.

## 도구부터 돌린다

```bash
python3 도구/구조진단.py <레포경로>
python3 도구/구조진단.py <레포경로> --자세히    # 항목별 전체 목록
```

**아무것도 고치지 않는다. 재기만 한다.** 결과는 두 칸으로 나뉜다.

```
고칠 것   그대로 두면 나중에 누가 틀린 걸 보게 되는 자리
참고      신호일 뿐이다. 정상일 수도 있으니 눈으로 본다
```

## 무엇을 재나

| 잰 것 | 왜 |
|---|---|
| 깨진 링크 | 읽는 사람이 그 자리에서 막힌다. 가장 먼저 고친다 |
| **한 파일에 같은 절이 두 번** | 낡은 판과 새 판이 같이 산다. 사람은 위에 있는 걸 본다 |
| 크기 초과 | 길면 읽다가 빠뜨린다. 성격별로 상한이 다르다 |
| 폴더 과밀 · 깊이 초과 | 찾다가 포기하고 새로 만든다 → 중복이 는다 |
| 같은 제목이 여러 파일에 | 같은 규칙이 두 곳에 적혀 있을 수 있다 |
| 아무도 안 가리키는 파일 | 죽은 파일이거나, 목차가 빠졌거나 |
| 뒤처진 문서 | 레포 기준 연도보다 3년 이상 뒤 |

★ **"한 파일에 같은 절이 두 번" 이 이 도구의 값어치다.** 제목이 똑같아야 잡히는 게 아니라
**앞부분만 같아도** 잡는다. 실제로 겪은 모양이 이랬다.

```
## H · 홈페이지 (2026-09-02 시작 — 전부 B)     ← 낡은 판
## H · 홈페이지와 법령 (2026-09-02 시작)        ← 새 판
```

**두 표가 나란히 있으면 사람은 위엣것을 본다.** 그래서 낡은 판으로 판단하게 된다.

## 도구가 못 재는 것 — 손으로 본다

```
□ 같은 사실이 서로 다르게 적힌 곳이 있나        (도구는 제목만 본다)
□ 앞머리(frontmatter)의 등급·상태가 본문과 맞나
□ 문서가 가리키는 경로가 실제 폴더 이름과 맞나  (폴더를 옮기면 잘 어긋난다)
□ "지금 안 쓰는 것" 이 어디까지인지 적혀 있나
```

**실제로 이 창고에서 나온 어긋남**

```
· 파일 앞머리는 등급 B 인데 본문과 레지스트리는 A         ← 승급이 한 곳에만 반영
· 레지스트리의 보관 경로가 폴더 재편 전 값                ← 폴더를 옮기고 참조를 안 고침
· "전부 B" 라고 적힌 표와 "대부분 A" 인 표가 같은 파일에   ← 위엣것을 보고 판단하게 됨
```

## 재고 나면 한 장으로 적는다

정리를 시작하기 전에 **현재 상태를 한 장에 적어 둔다.** 나중에 무엇이 나아졌는지
말할 수 있어야 한다.

```
■ 실측 (YYYY-MM-DD)
파일 __개 / 글 __개 / 폴더 __개
고칠 것 __건   · 깨진 링크 __ · 같은 절 두 번 __ · 크기 초과 __ · 과밀 __
참고 __건
손으로 찾은 어긋남:
```

**이 한 장이 없으면 정리가 끝났는지 아무도 모른다.**
