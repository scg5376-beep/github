# 5단계 · 검사기를 심는다

> **구조는 사람이 지키지 않는다.** 바쁘면 규칙을 잊는다. 그게 정상이다.
> 그래서 마지막에 **검사기를 레포 안에 심고, 커밋 전에 돌리는 습관**을 만든다.

## 진단 도구를 레포로 옮긴다

```
1  도구/구조진단.py 를 레포 안에 복사한다  (예: 도구/ 또는 scripts/)
2  파일 맨 위 상수를 그 레포에 맞게 고친다
       상한 · 폴더상한 · 깊이상한 · 항상로드 · 보관성폴더
3  README 나 CLAUDE.md 의 "커밋 전에" 자리에 한 줄 넣는다
```

**상한을 그 레포에 맞게 고치는 게 핵심이다.** 남의 숫자를 그대로 쓰면
매번 걸리고, 매번 걸리면 사람이 검사기를 무시하게 된다.

## 검사기가 잡아야 할 것을 그 레포 말로 적는다

일반 도구가 못 잡는 건 **그 레포만의 규칙**이다. 작은 검사기를 따로 만든다.

```
· 앞머리(frontmatter)의 필수 칸이 비었나
· 목차에 없는 폴더가 생겼나            ← 이게 특히 값어치 있다
· 이 레포에 들어오면 안 되는 말이 섞였나 (다른 사업체 이름 · 개인정보 · 열쇠값)
· 서로 가리키는 두 값이 어긋났나        (등급 · 상태 · 경로)
```

★ **"목차에 없는 폴더가 생겼나" 를 꼭 넣는다.** 폴더가 조용히 늘어나는 게
구조가 무너지는 첫 신호다.

## 규칙을 두 곳에 쓰지 않는다 — 검사기끼리도

검사기가 둘 이상이면 **같은 판정 규칙을 복사하지 않는다.** 하나에서 불러 쓴다.

```python
import brand_check as BC        # 판정 규칙은 저기 한 곳에만 있다
... BC.전화.findall(줄) ...
```

복사해 두면 한쪽만 고치게 되고, 그때부터 두 검사기가 다른 말을 한다.

## 검사기를 넓힐 때는 반드시 되짚어 본다

오탐이 나와서 규칙을 느슨하게 만들었으면, **진짜를 여전히 잡는지 확인한다.**

```
1  오탐이 나는 문장을 예외로 넣는다
2  진짜 걸려야 하는 값을 일부러 넣어 본다
3  여전히 잡히는지 확인하고 지운다
4  넓힌 이유를 코드 주석에 날짜와 함께 적는다
```

**실제로 겪은 것** — 검사기가 인용문 속 "간략한 설명으로 1-2개의" 를 주소로 잡았다.
인용문은 고칠 수 없으니 검사기를 넓혔고, 넓힌 뒤 진짜 주소를 넣어 여전히 잡히는 걸
확인하고 지웠다. **확인 기록에 그 예시 주소를 그대로 적었더니 검사기가 또 잡았다 —
옳게 동작한 것이다.** 기록에도 진짜 형태의 값을 적지 않는다.

## 커밋 전 한 줄로 만든다

```bash
python3 도구/구조진단.py .        # 구조
python3 도구/○○_check.py         # 이 레포만의 규칙
```

**이 두 줄을 README 와 CLAUDE.md 의 같은 자리에 적는다.**
사람이 잊어도 다음 사람이 본다.

## 검사기가 통과한다고 내용이 맞는 건 아니다

```
검사기가 보는 것    구조 · 형식 · 중복 · 경로
검사기가 못 보는 것  사실이 맞나 · 최신인가 · 서로 말이 되나
```

**형식 검사를 통과했다고 정리가 끝난 게 아니다.** 마지막에 사람이 읽는다.
