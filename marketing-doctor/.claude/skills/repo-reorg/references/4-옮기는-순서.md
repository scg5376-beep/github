# 4단계 · 옮기는 순서

> **한 번에 하나씩.** 여러 개를 같이 옮기면 무엇이 깨졌는지 못 찾는다.
> 그리고 **지우기 전에는 반드시 사람에게 확인받는다.**

## 절대 규칙 — 삭제는 제안하고 승인받는다

```
❌ 안 쓰는 것 같아서 지웠다
⭕ "이 넷은 안 쓰이는 것으로 보입니다. 지울까요, 보관 자리로 옮길까요?"
```

**정리 작업에서 신뢰를 잃는 자리는 거의 항상 삭제다.**
옮기고 이름 바꾸는 건 되돌릴 수 있지만, 지운 걸 못 알아채면 되돌릴 기회조차 없다.

## 한 덩어리를 옮기는 순서

```
0  옮기기 전에 참조를 센다
     grep -rn "옛이름" . --include=*.md --include=*.yaml
     몇 곳이 걸리는지 먼저 안다. 열 곳이면 열 곳을 다 고칠 각오로 시작한다

1  git mv 로 옮긴다  (rm + 새로 만들기 금지 — 이력이 끊긴다)

2  참조를 전부 고친다
     문서 안 링크 · 설정 파일의 경로 · 코드 안 경로 · 목차 · 라우팅 표

3  다시 센다
     grep -rn "옛이름" .        → 0 이어야 한다

4  검사기를 돌린다
     python3 도구/구조진단.py .

5  커밋한다. 메시지에 왜 옮겼는지 적는다
```

**2번을 빼먹는 게 가장 흔한 사고다.** 실제로 폴더를 가른 뒤
참조 열넷(문서 7 · 기록 2 · 설정 2 · 목차 3)을 같이 고쳐야 했다.

## 한 번에 하나 — 무엇이 '하나' 인가

```
하나다      한 폴더를 가른다 · 한 파일을 둘로 나눈다 · 한 규칙을 한 곳으로 모은다
하나가 아니다  폴더를 가르면서 이름도 바꾸고 내용도 고친다
```

**구조를 바꾸는 커밋과 내용을 고치는 커밋을 섞지 않는다.**
섞으면 나중에 "이 문장이 왜 이렇게 됐지" 를 추적할 수 없다.

## 내용이 서로 어긋날 때

낡은 판과 새 판이 같이 있으면 **어느 쪽이 맞는지 근거로 정한다.**

```
1  두 판의 다른 점을 나란히 적는다
2  근거를 찾는다 — 원본 문서 · 커밋 날짜 · 다른 문서와의 일치
3  근거로 못 정하면 사람에게 묻는다. 추측으로 하나를 지우지 않는다
4  정한 뒤 낡은 판을 지운다 (승인받고)
5  왜 두 벌이 생겼는지 한 줄 남긴다
```

## 큰 개편은 단계로 쪼갠다

**한 번에 다 바꾸면 검토가 불가능해진다.** 이 순서가 안전하다.

```
1  실측하고 한 장으로 적는다              (아무것도 안 고침)
2  깨진 링크만 고친다                     (되돌릴 일 없음)
3  낡은 판 · 중복 절을 정리한다            (승인 필요)
4  폴더 구조를 바꾼다                     (참조를 같이 고침)
5  목차와 라우팅 표를 다시 쓴다
6  검사기를 심는다
7  마지막에 실측을 다시 해서 나란히 놓는다
```

각 단계마다 커밋을 나눈다. **되돌릴 수 있는 상태를 계속 유지한다.**
