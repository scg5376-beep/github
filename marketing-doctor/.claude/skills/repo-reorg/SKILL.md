# 레포 구조 개편

> **정리가 목적이 아니다.** 그 레포에서 실제로 일이 돌아가게 만드는 게 목적이다.
> 그래서 마지막 단계는 "깔끔해졌다" 가 아니라 **"내일 시작할 수 있다"** 다.

## 절대 지키는 것 셋

### ① 지우기 전에 반드시 확인받는다

```
❌ 안 쓰는 것 같아서 지웠다
⭕ "이 넷은 안 쓰이는 것으로 보입니다. 지울까요, 보관 자리로 옮길까요?"
```

옮기고 이름 바꾸는 건 되돌릴 수 있다. **지운 걸 못 알아채면 되돌릴 기회조차 없다.**
정리 작업에서 신뢰를 잃는 자리는 거의 항상 삭제다.

### ② 재기 전에 고치지 않는다

감으로 시작하면 반드시 뭔가를 잃는다. **숫자로 본 다음에 손을 댄다.**

### ③ 한 번에 하나씩

구조를 바꾸는 커밋과 내용을 고치는 커밋을 섞지 않는다.
섞으면 나중에 "이 문장이 왜 이렇게 됐지" 를 추적할 수 없다.

## 순서

```
1단계  먼저 잰다              references/1-먼저-재는-법.md
       └ 도구/구조진단.py 를 돌린다. 아무것도 안 고친다

2단계  종류별 처방            references/2-무엇이-문제인가.md
       └ 항목마다 하는 일이 다르다

3단계  구조를 정한다          references/3-구조-정하는-법.md
       └ 폴더가 곧 성격이다. 주제로 가르지 않는다

4단계  옮긴다                 references/4-옮기는-순서.md
       └ 참조를 먼저 세고, 옮기고, 다시 센다

5단계  검사기를 심는다        references/5-검사기-심는-법.md
       └ 사람은 규칙을 잊는다. 그게 정상이다

6단계  시작 상태로 넘긴다     references/6-마케팅-시작-상태로-넘기기.md
       └ 자리 0 · 보고/ · 스킬. 여기까지 해야 끝이다
```

## 제일 먼저 잡아야 할 것

**한 파일 안에 같은 절이 두 번 있는 자리.**

```
## H · 홈페이지 (전부 B)        ← 낡은 판
## H · 홈페이지와 법령           ← 새 판
```

**두 표가 나란히 있으면 사람은 위엣것을 본다.** 그래서 낡은 판으로 판단하게 된다.
진단 도구는 제목이 똑같지 않아도 **앞부분만 같으면** 잡는다.

## 이 스킬이 밑에 깔고 있는 원칙

```
폴더가 곧 성격이다        주제가 아니라 "얼마나 낡나 · 고치는 것인가" 로 가른다
상한은 올리지 않는다      부딪히면 성격으로 나눈다. 올린 자리는 반드시 또 부딪힌다
규칙은 한 곳에만          두 곳에 적으면 한 곳만 고치게 된다. 누락의 가장 큰 원인
안 쓰는 것도 지우지 않는다  보관 자리로 옮기고 "왜 안 쓰는지" 를 적는다
검사기를 심는다          구조를 사람이 계속 지킬 거라고 믿지 않는다
```

## 첫날 할 일

```
□ python3 도구/구조진단.py <레포경로>
□ 결과를 한 장으로 적는다 (지금 상태. 나중에 비교할 기준이 된다)
□ '고칠 것' 중 깨진 링크부터 고친다 — 되돌릴 일이 없는 작업이다
□ '같은 절이 두 번' 목록을 사람에게 보여 주고 어느 쪽이 낡은 판인지 정한다
```

**넷째 줄이 제일 중요하다.** 그건 혼자 정하면 안 된다.
