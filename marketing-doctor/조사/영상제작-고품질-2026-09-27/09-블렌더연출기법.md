# 09. 블렌더 연출 기법 — bpy 자동 생성용 정리 (2026-09-28)

> 목적: 분양 광고(세로 1080×1920, 30fps)에 쓸 「진짜 아름다운」 전환·연출 5종 이상을
> **Blender 5.x(bpy) 로 자동 조립**할 수 있게, 노드·설정·코드 뼈대까지 구체화한다.
> 환경: Blender 5.2.1 LTS(`%LOCALAPPDATA%\Programs\blender\blender-5.2.1-windows-x64\blender.exe`),
> 배치 모드 `blender -b -P 스크립트.py -- 인자`, RTX 5060.

## ★★ 가장 중요한 발견 — Blender 5.x 는 예전 튜토리얼 노드 이름이 안 맞는다

유튜브 강의 대부분(2019~2024, Blender 2.9~4.x)은 **지금과 다른 API/노드 이름**을 쓴다.
그대로 베끼면 배치 모드에서 즉시 에러가 난다. bpy 로 직접 돌려서 확인한 차이:

| 예전(강의에서 말하는 것) | Blender 5.2.1 에서 실제로 되는 것 | 확인 방법 |
|---|---|---|
| `scn.render.engine = "BLENDER_EEVEE_NEXT"` | **`"BLENDER_EEVEE"`** 만 있음(EEVEE Next 가 EEVEE 자리를 차지) — enum: `BLENDER_EEVEE, BLENDER_WORKBENCH, CYCLES` | 직접 실행해 TypeError 확인 |
| 컴포지터 `scene.node_tree` | **`scene.compositing_node_group`** (컴포지터가 5.0부터 **노드 그룹** 자체가 됐다 — Motion Dreams 강의도 "Blender 5.0 에서는 좀 다르다"고 언급) | `dir(scn)` 로 확인 |
| 컴포지터 출력 `CompositorNodeComposite` | 없음. **`NodeGroupOutput`** 을 쓰고, 트리 `interface.new_socket("Image", in_out="OUTPUT", socket_type="NodeSocketColor")` 를 먼저 만든다 | `nodes.new()` 로 실증 |
| 컴포지터 `CompositorNodeValToRGB`(컬러램프), `CompositorNodeMixColor`, Math 노드 | 컴포지터 전용 타입이 없어졌다. **셰이더 노드를 그대로 씀**: `ShaderNodeValToRGB`(컬러램프), `ShaderNodeMix`(`data_type="RGBA"`), `ShaderNodeMath`, `ShaderNodeTexNoise` — "에브리씽 노드"(노드 타입 공유) 방향이 컴포지터까지 온 것 | 92개 `CompositorNode*` 타입을 전수 조회해서 확인(Ramp·Math 없음) → Shader 계열이 대신 `nodes.new()` 성공 |
| `mat.use_nodes = True` | 여전히 동작하지만 **Blender 6.0 에서 제거 예정**이라고 DeprecationWarning 뜸(재질은 이제 항상 노드 기반이라 이 스위치 자체가 없어질 예정) | 실행 로그에서 경고 확인 |
| Geometry Nodes 의 "Attribute Vector Math", "Point Distribute", "Point Instance" (Entagma 등 옛 강의) | 필드(field) 시스템으로 통합됨. 이름 없는 계산은 그냥 `ShaderNodeVectorMath`/`ShaderNodeMath` 를 체인으로 연결하면 되고, 점 배치는 `GeometryNodeDistributePointsOnFaces`, 인스턴스는 `GeometryNodeInstanceOnPoints`. 여러 노드 트리에 걸쳐 값을 넘길 때만 `GeometryNodeCaptureAttribute`/이름 붙은 속성을 쓴다 | 일반 지식 + 5.2.1 API 존재 확인(`GeometryNodeSetPosition`, `GeometryNodeInputSceneTime` 등 정상 생성됨) |

**결론: 강의 자막에서 나온 노드 "이름"은 원리 학습용으로만 쓰고, 실제 bpy 코드는 이 문서의 확인된 이름을 쓴다.**

## 기법 1 — 파티클/조각 분해 전환 (디졸브 리빌)

**원리**: 화면을 채운 판(또는 3D 오브젝트)을 아주 잘게 쪼갠 뒤, 각 조각을 노멀 방향+노이즈로 흩날려 사라지게 하면 그 뒤에서 다음 장면(아파트)이 드러난다. 세 갈래 구현이 있다.

1. **면 단위 붕괴(CGMatter식, 실측 확인)** — `Split Edges` 로 면을 개별 조각화 → `Set Position` 으로 노멀 방향 오프셋 → 오프셋 세기를 `Geometry Proximity`(트리거 오브젝트와의 거리)로 제어.
2. **가중치 폴오프(Entagma식)** — 3D 직선(두 Empty) + 벡터 내적으로 진행률(0~1) 계산 → 그 값으로 인스턴스 스케일·이동·노이즈 워프.
3. **컬러램프+델리트(Ducky 3D식)** — 노이즈 텍스처를 컬러램프로 스레숄드해 `Delete Geometry` 의 선택 입력에 연결, 애니메이션은 컬러램프 위치를 키프레임.

세로 광고에는 (1)이 가장 가볍고 자동화하기 쉽다 — 트리거 오브젝트(빈 구)를 화면 위→아래로 이동시키면 붕괴가 훑고 지나간다.

### 노드 그래프(면 단위 붕괴, 동작 확인함)

```
Group Input(Geometry)
  → Subdivide Mesh(Level=6)        # 격자를 잘게
  → Split Edges                    # 면을 개별화
  → Set Position
       Offset = Normal × (Noise(Position).Fac × 세기)
       세기 = 1 - clamp(map_range(Geometry Proximity(트리거).Distance))
  → Group Output(Geometry)
```

### bpy 코드 뼈대 (동작 확인 — `t1_dissolve.py`)

```python
import bpy, math

bpy.ops.mesh.primitive_plane_add(size=4)
plane = bpy.context.active_object
mod = plane.modifiers.new("Nodes", "NODES")
tree = bpy.data.node_groups.new("DissolveGN", "GeometryNodeTree")
mod.node_group = tree

# 5.x 인터페이스는 tree.interface (구 inputs/outputs 아님)
tree.interface.new_socket("Geometry", in_out="INPUT", socket_type="NodeSocketGeometry")
tree.interface.new_socket("Geometry", in_out="OUTPUT", socket_type="NodeSocketGeometry")

nodes, links = tree.nodes, tree.links
n_in  = nodes.new("NodeGroupInput")
n_out = nodes.new("NodeGroupOutput")
n_subdiv = nodes.new("GeometryNodeSubdivideMesh"); n_subdiv.inputs["Level"].default_value = 6
n_split  = nodes.new("GeometryNodeSplitEdges")
n_pos    = nodes.new("GeometryNodeInputPosition")
n_normal = nodes.new("GeometryNodeInputNormal")
n_noise  = nodes.new("ShaderNodeTexNoise"); n_noise.inputs["Scale"].default_value = 3.0
n_time   = nodes.new("GeometryNodeInputSceneTime")
n_mul1 = nodes.new("ShaderNodeVectorMath"); n_mul1.operation = "MULTIPLY"
n_mul2 = nodes.new("ShaderNodeVectorMath"); n_mul2.operation = "SCALE"
n_setpos = nodes.new("GeometryNodeSetPosition")

links.new(n_in.outputs["Geometry"], n_subdiv.inputs["Mesh"])
links.new(n_subdiv.outputs["Mesh"], n_split.inputs["Mesh"])
links.new(n_split.outputs["Mesh"], n_setpos.inputs["Geometry"])
links.new(n_pos.outputs["Position"], n_noise.inputs["Vector"])
links.new(n_normal.outputs["Normal"], n_mul1.inputs[0])
links.new(n_noise.outputs["Fac"], n_mul1.inputs[1])
links.new(n_mul1.outputs["Vector"], n_mul2.inputs[0])
links.new(n_mul2.outputs["Vector"], n_setpos.inputs["Offset"])
links.new(n_setpos.outputs["Geometry"], n_out.inputs["Geometry"])
```

프록시미티(트리거로 붕괴가 훑고 지나가게)는 위 `n_mul2.inputs["Scale"]` 자리에
`GeometryNodeProximity`(입력 Geometry=트리거 오브젝트, 출력 Distance) →
`Map Range`(Distance를 0~1로) → `1 - x` 를 연결한다. `GeometryNodeProximity` 는
5.2.1에서 `Position`(3), `Distance`(1), `Is Valid`(2) 세 출력을 낸다(실측 확인).

### 렌더 설정·시간

- RGBA 알파 렌더로 조각 장면만 뽑고, 뒤의 아파트 영상과 컴포지터에서 합성(Alpha Over 대신 `ShaderNodeMix` RGBA, Factor=알파).
- EEVEE, 1080×1920, 30fps, 조각 전환 구간 1~1.5초(30~45프레임)면 충분 — 너무 길면 지루하다(Ducky 3D 도 "너무 빠르면 감상이 안 되고, 적당한 속도가 낫다"고 언급).
- 조각 수(Subdivide Level)가 크면(7 이상) EEVEE 라도 렌더가 느려진다 — 세로 프레임 기준 Level 5~6 권장.

### 흔한 실패

- `BLENDER_EEVEE_NEXT` 로 엔진을 설정하면 TypeError(위 표 참고).
- Split Edges 없이 Set Position 만 하면 조각이 아니라 메시 전체가 뭉개진다(면이 서로 붙어 있어서).
- 컬러램프 방식(Ducky 3D)은 재질 두 개를 Mix Shader 로 겹치는 구조라 **셰이더 쪽**(Material)에서 하는 것이지 지오메트리 노드가 아니다 — 혼동하지 말 것.

## 기법 2 — 3D 입체 교통 지도

**원리**: 실제 지도(SVG)를 3D 커브/메시로 올리고, 노선은 별도 커브에 원형 프로파일을 씌운 "빛나는 선"으로 만들어 `Trim Curve` 로 그려지게 한다. 카메라는 기울어진 채로 서서히 이동.

### 2-A. 지형(건물·국경) — SVG 임포트 + 압출

1. 환경설정 → 애드온 → "Import Scalable Vector Graphics" 활성화(내장 애드온, Bhagath Goud 강의).
2. `bpy.ops.import_curve.svg(filepath=...)` 로 임포트하면 커브 오브젝트 여러 개가 생긴다.
3. 각 커브의 `data.extrude`(압출 깊이), `data.bevel_depth`(모서리 둥글기)를 설정 — "Copy to Selected" 로 여러 국가/블록에 한 번에 적용(강의에서 우클릭 메뉴로 시연).
4. 지도 SVG는 **출처 라이선스를 확인**(상업 이용 가능 여부) — 이건 조사자가 판단할 수 없으니 **운영자확인필요**.

### 2-B. 빛나는 노선 — Curve to Mesh + Trim Curve (동작 확인 — `t2_curveline.py`)

```python
import bpy

bpy.ops.curve.primitive_bezier_curve_add()
curve = bpy.context.active_object
bc = curve.data.splines[0].bezier_points
bc[0].co = (-2, -2, 0); bc[1].co = (2, 2, 0)   # 노선 경로(핸들 조정으로 곡선화)

mod = curve.modifiers.new("Nodes", "NODES")
tree = bpy.data.node_groups.new("LineGN", "GeometryNodeTree")
mod.node_group = tree
tree.interface.new_socket("Geometry", in_out="INPUT",  socket_type="NodeSocketGeometry")
tree.interface.new_socket("Geometry", in_out="OUTPUT", socket_type="NodeSocketGeometry")
nodes, links = tree.nodes, tree.links
n_in, n_out = nodes.new("NodeGroupInput"), nodes.new("NodeGroupOutput")

n_trim = nodes.new("GeometryNodeTrimCurve")
n_trim.inputs[2].default_value = 0.0   # Start(Factor 모드, 소켓 인덱스 2)
n_trim.inputs[3].default_value = 0.6   # End   (Factor 모드, 소켓 인덱스 3) — 이 값을 키프레임
n_circle = nodes.new("GeometryNodeCurvePrimitiveCircle")
n_circle.inputs["Radius"].default_value = 0.03
n_c2m = nodes.new("GeometryNodeCurveToMesh")
n_shade = nodes.new("GeometryNodeSetShadeSmooth")

links.new(n_in.outputs["Geometry"], n_trim.inputs["Curve"])
links.new(n_trim.outputs["Curve"], n_c2m.inputs["Curve"])
links.new(n_circle.outputs["Curve"], n_c2m.inputs["Profile Curve"])
links.new(n_c2m.outputs["Mesh"], n_shade.inputs["Geometry"])
links.new(n_shade.outputs["Geometry"], n_out.inputs["Geometry"])

mat = bpy.data.materials.new("Glow"); mat.use_nodes = True
bsdf = mat.node_tree.nodes["Principled BSDF"]
bsdf.inputs["Emission Strength"].default_value = 5.0
bsdf.inputs["Emission Color"].default_value = (0.2, 0.7, 1.0, 1.0)
curve.data.materials.append(mat)
```

`GeometryNodeTrimCurve` 의 소켓은 실측 확인 결과 `0 Curve, 1 Selection, 2 Start(Factor), 3 End(Factor), 4 Start(Length), 5 End(Length)` — 모드는 `n_trim.mode = 'FACTOR'`(기본) 또는 `'LENGTH'`. **End(소켓 3)를 0→1로 키프레임하면 선이 그려지는 애니메이션이 된다** — 렌더 이미지로 실측: 절반(0.6)까지 정확히 잘려 나온 직선을 확인했다.

끝점을 둥글게 하려면(Xan 3D 강의) 시작·끝에 `Instance on Points`로 작은 구를 얹고 `Join Geometry`.

### 카메라·렌더

- 지도를 살짝 기울여(오브젝트 회전 X축 20~30도) 부감으로 보이게 하고, 카메라는 낮은 각도에서 서서히 팬/돌기(Empty에 Track To 컨스트레인트로 지도 중심을 보게).
- EEVEE 블룸(Bloom) 켜면 발광 노선이 더 산다 — `scn.eevee.use_bloom = True`(속성명은 버전별로 다를 수 있어 `hasattr` 체크 필수, `blender_apt.py` 의 방식 참고).
- 렌더 시간: 노선 몇 개 + 지형 정도면 EEVEE 로 프레임당 1초 미만.

### 흔한 실패

- SVG 임포트 애드온이 꺼져 있으면 `import_curve.svg` 오퍼레이터 자체가 없다고 뜬다 — 배치 모드에서는 `bpy.ops.preferences.addon_enable(module="io_curve_svg")` 를 스크립트 안에서 먼저 해줘야 한다(**미확인** — 애드온 이름 정확한 모듈명은 5.2.1 기준 재확인 필요).
- Trim Curve 를 Curve to Mesh **뒤에** 연결하면 메시는 안 잘리고 프로파일만 이상해진다 — 반드시 커브 단계에서 자른다.

## 기법 3 — 3D 갤러리 플라이스루 (영상·사진을 띄운 판 사이로 카메라 이동)

**원리**: 사진/영상을 각각 평면(Plane)에 입히고, 여러 평면을 공간에 배치한 뒤 카메라가 그 사이를 관통 비행. 영상 소재는 Image Texture 를 **Movie 소스**로 쓰면 판이 곧 재생 화면이 된다.

### 영상 텍스처를 판에 입히는 법 (미확인 — bpy 실행 시험 안 함, 공식 API 지식 기반)

```python
img = bpy.data.images.load("C:/경로/클립.mp4")   # Movie 는 load 로 불러오면 자동으로 source='MOVIE'
img.source = 'MOVIE'

mat = bpy.data.materials.new("VideoPlane"); mat.use_nodes = True
nt = mat.node_tree
tex = nt.nodes.new("ShaderNodeTexImage")
tex.image = img
tex.image_user.frame_duration = img.frame_duration
tex.image_user.frame_start = 1
tex.image_user.frame_offset = 0          # 판마다 다른 오프셋을 주면 각기 다른 시점부터 재생
tex.image_user.use_auto_refresh = True   # 프레임이 바뀔 때 자동 갱신
nt.links.new(tex.outputs["Color"], nt.nodes["Principled BSDF"].inputs["Base Color"])
```

`ShaderNodeTexImage.image_user` 가 Movie 소스의 프레임 제어(Start Frame·Frame Offset·Auto Refresh)를 갖는다는 것은 Blender 공식 API 문서(`ImageUser` 타입)에 근거하지만, **이번 조사에서 실제로 mp4 를 렌더까지 돌려 확인하지는 못했다** — 자막 검색에서 "판 위의 영상" 강의는 조회수 낮은 짧은 영상뿐이라 자막 정독을 안 했다. **다음 세션에서 실측 필요.**

### 배치·카메라

- 판을 Z(깊이)와 X/Y 로 흩뿌려 공간감 — Empty 를 부모로 두고 `Array`+`Randomize` 모디파이어 조합, 또는 파이썬 반복문으로 좌표를 랜덤 배치.
- 카메라는 하나의 커브를 따라가는 Follow Path 컨스트레인트로 판 사이를 관통(경로는 기법2 의 Trim Curve 와 달리 카메라 자체를 커브에 바인딩 — `bpy.ops.object.parent_set(type='FOLLOW')` 또는 `Follow Path` 컨스트레인트).
- 판이 카메라를 향하게 하려면 `Track To` 컨스트레인트(타깃=카메라)로 항상 정면이 보이게 할 수도 있다(디스플레이 벽처럼).

### 흔한 실패(예상, 미확인)

- mp4 코덱에 따라 Blender 가 못 읽는 경우가 있다 — ffmpeg 로 h264 mp4 로 통일 필요(`blender_cut.py` 관례와 동일).
- 판 여러 장에 영상을 동시 재생하면 메모리·디코딩 부하가 커진다 — 판 수를 6~10장 이하로 제한 권장(미확인, 추정치).

## 기법 4 — 유기적 마스크 리빌 (잉크 번짐·빛 번짐)

**원리**: 노이즈 텍스처를 컬러램프(스레숄드)로 이진화해 마스크를 만들고, 그 경계를 `Dilate/Erode`(팽창·침식)와 `Bilateral Blur`(경계만 부드럽게, 안쪽은 안 뭉개지게)로 다듬어 "번짐"처럼 보이게 한다. 마스크의 임계값이나 확산 반경을 시간에 따라 바꾸면 전환이 된다.

### ★ Blender 5.x 컴포지터는 노드 그룹이다 (동작 확인 — `t4_compmask.py`)

```python
import bpy

scn = bpy.context.scene
ctree = bpy.data.node_groups.new("Compositor", "CompositorNodeTree")
ctree.interface.new_socket("Image", in_out="OUTPUT", socket_type="NodeSocketColor")
scn.compositing_node_group = ctree     # scn.node_tree 아님(5.x 부터 없음)

nodes, links = ctree.nodes, ctree.links
n_rl   = nodes.new("CompositorNodeRLayers")
n_noise = nodes.new("ShaderNodeTexNoise")          # 컴포지터에도 셰이더 텍스처 노드를 그대로 씀
n_ramp  = nodes.new("ShaderNodeValToRGB")          # CompositorNodeValToRGB 는 존재하지 않음(실측)
n_ramp.color_ramp.interpolation = "CONSTANT"
n_ramp.color_ramp.elements[0].position = 0.45
n_ramp.color_ramp.elements[1].position = 0.55
n_mix = nodes.new("ShaderNodeMix"); n_mix.data_type = "RGBA"   # A/B/Result 는 RGBA 소켓 세트 사용
n_out = nodes.new("NodeGroupOutput")               # CompositorNodeComposite 는 존재하지 않음(실측)

links.new(n_noise.outputs["Fac"], n_ramp.inputs["Fac"])
links.new(n_ramp.outputs["Color"], n_mix.inputs[0])      # Factor
links.new(n_rl.outputs["Image"], n_mix.inputs[6])        # A(RGBA)
links.new(n_rl.outputs["Image"], n_mix.inputs[7])        # B(RGBA)
links.new(n_mix.outputs[2], n_out.inputs["Image"])       # Result(RGBA)
```

`ShaderNodeMix` 를 RGBA 로 쓰면 입력이 `Factor(0), Factor(1,Vector용), A(2,Value), B(3,Value), A(4,Vector), B(5,Vector), A(6,RGBA), B(7,RGBA), A(8,Rotation), B(9,Rotation)` 순서로 늘어선다(실측). 출력도 타입별로 4개 나오고 RGBA 결과는 `outputs[2]`.

### 번짐 디테일 (강의 기반, MarginallyCompetent — 노드 이름은 5.x 로 치환 필요, 부분 확인)

- 명도 4단계(가장 어두운 잉크 → 가장 밝은 잉크)로 나눠 각각 컬러램프(Constant 보간)로 이진화, `Dilate/Erode`(구 이름 `CompositorNodeDilateErode`, 5.2.1 에도 **존재함** — Feather/Sphere/Threshold 세 모드) 로 5px 안팎 팽창.
- 경계 흐림은 `CompositorNodeBilateralblur`(5.2.1 존재 확인, 이름만 확인 — 파라미터 실측은 안 함)에 노이즈 텍스처를 디터미네이터로 물려 얼룩덜룩하게.
- 원형 확산은 `CompositorNodeEllipseMask`(존재 확인)의 width/height 를 0→1 로 키프레임 + `CompositorNodeDisplace`(존재 확인)로 경계를 보로노이 노이즈로 흔든다.
- 여러 마스크를 겹칠 때는 `ShaderNodeMix`(RGBA)를 계단식으로 연결(Alpha Over 대신).

이 문단의 개별 노드(Dilate/Erode, Bilateral Blur, Ellipse Mask, Displace)는 **타입 존재만 실측 확인**했고, 파라미터 조합까지 렌더로 검증하지는 못했다 — **미확인**.

### 렌더 시간

- 마스크·컴포지터 연산은 EEVEE 렌더 자체보다 가볍다. 다만 노이즈 텍스처 변수가 많으면 컴포지터 프리뷰가 느려질 수 있다(경험적 추정, 미확인).

## 기법 5 — 3D 로고·타이틀 리빌 (엔딩)

**원리**: 단지명을 Text 오브젝트로 만들어 압출·베벨로 두께를 주고, 유리/금속 재질에 빛이 스치게 하거나(단순 버전) SVG 로고를 커브로 잘라 볼륨 안개 뒤에서 빛으로 드러낸다(고급 버전, Motion Dreams — Blender 5.0 촬영).

### 5-A. Text 오브젝트 3D화 + 한글 폰트 (동작 확인 — `t5_text.py`)

```python
import bpy, glob

bpy.ops.object.text_add()
txt = bpy.context.active_object
txt.data.body = "한강 분양 단지"

font_path = "C:/Windows/Fonts/malgun.ttf"   # 맑은 고딕. Pretendard 를 쓰려면 해당 ttf 경로로 교체
txt.data.font = bpy.data.fonts.load(font_path)

txt.data.extrude = 0.05      # 두께
txt.data.bevel_depth = 0.01  # 모서리 둥글기
txt.data.align_x = "CENTER"
txt.data.align_y = "CENTER"

mat = bpy.data.materials.new("Metal"); mat.use_nodes = True
b = mat.node_tree.nodes["Principled BSDF"]
b.inputs["Metallic"].default_value = 1.0
b.inputs["Roughness"].default_value = 0.15
txt.data.materials.append(mat)
```

렌더로 실측: 한글("한강 분양 단지")이 맑은 고딕으로 로드되고, 압출·베벨·금속 재질(반사 하이라이트)이 정상 렌더됐다. **Pretendard 같은 별도 폰트 파일을 쓰려면 해당 `.ttf`/`.otf` 경로만 바꾸면 된다**(로드 방식은 동일 — `title_render.py` 가 이미 Pretendard 경로를 쓰고 있으니 거기서 경로를 가져오면 됨, `marketing-doctor/엔진/영상분석/title_render.py`).

카메라가 다가가며(Track To + Z축 이동 애니메이션) 빛(Area Light 하나를 좌우로 슬라이드)이 스치게 하면 "빛이 흐르는" 느낌이 난다 — 빛 위치를 키프레임.

### 5-B. 볼류메트릭 로고 리빌 (강의 요지 정리, 미확인 — 시간 관계상 bpy 시험 안 함)

1. SVG 로고 임포트 → 압출 → Boolean 모디파이어로 두꺼운 박스에서 로고 모양만 뚫는다(Boolean, Difference/Intersect 방식은 로고를 "구멍"으로 만들지 "돌출"로 만들지에 따라 선택).
2. 스팟라이트를 박스 뒤에 두고 강한 파워(수천 W)로 설정, 박스 재질에 `Principled Volume` 노드를 볼륨 출력에 연결 → 안개 속에서 로고 구멍으로만 빛이 새어 나온다.
3. 볼륨에 노이즈 텍스처(4D, W축에 `#frame/200` 드라이버)를 넣어 안개가 시간에 따라 흐르게.
4. 렌더 설정에서 Volumetric Shadows 켜기, Volume Custom Range 로 카메라~조명 거리 안쪽만 렌더(속도 절약).
5. 컴포지터에서 Glare 노드(Bloom·Streaks)를 겹쳐 광원 번짐 강화 — Glare 도 `CompositorNodeGlare` 로 5.2.1 존재 확인(파라미터는 미확인).

**Blender 5.0 볼륨 갱신 버그**: 원본 강의(Motion Dreams)가 "카메라 뷰를 나갔다 들어와야 볼륨이 갱신될 때가 있다"고 언급 — 배치 렌더(스크립트 실행)에서는 뷰포트를 안 거치니 이 문제가 재현되는지 **미확인**. 재현되면 매 프레임 렌더 전에 `bpy.context.view_layer.update()` 를 강제로 부르는 우회가 필요할 수 있다(추정, 미확인).

이 절 전체는 **원리 요약**이며 노드 이름·소켓은 5.2.1 기준으로 재검증이 필요하다(`GeometryNodeMeshBoolean` 존재는 통상적 지식이나 이번에 실측하지 않음).

## 기법 6 — 2.5D 시차(패럴랙스) (가능하면, 개념 정리 수준)

**원리**: 사진 한 장을 전경/중경/배경 등 깊이별 레이어(평면 여러 장, Z 위치 다름)로 나누고 카메라를 옆으로 이동(Trucking)시키면 가까운 레이어가 더 빨리 움직이며 입체감이 난다. 조사한 강의(Franklin chinonso)는 그리스펜슬 2D 오브젝트로 레이어를 그리는 방식을 썼지만, 우리 소재(실촬영 사진)에는 **평면(Plane) + 사진 텍스처**가 더 맞는다.

### bpy 뼈대 (미확인 — 개념만, 시험 안 함)

```python
import bpy

layers = [
    ("배경.png", -8, 1.0),   # (이미지경로, Z깊이, 스케일)
    ("중경.png", -4, 0.8),
    ("전경.png", -1, 0.5),
]
for path, z, scale in layers:
    bpy.ops.mesh.primitive_plane_add(location=(0, 0, z))
    p = bpy.context.active_object
    p.scale = (scale * 4, 1, scale * 4)
    mat = bpy.data.materials.new(f"L{z}"); mat.use_nodes = True
    tex = mat.node_tree.nodes.new("ShaderNodeTexImage")
    tex.image = bpy.data.images.load(path)
    mat.node_tree.links.new(tex.outputs["Color"],
        mat.node_tree.nodes["Principled BSDF"].inputs["Base Color"])
    p.data.materials.append(mat)

# 카메라를 X축으로 슬라이드(트러킹) — 가까운 레이어일수록 화면 이동량이 커 보임
cam = bpy.data.objects.new("Cam", bpy.data.cameras.new("Cam"))
bpy.context.scene.collection.objects.link(cam)
cam.location = (-2, -10, 0)
cam.keyframe_insert("location", frame=1)
cam.location = (2, -10, 0)
cam.keyframe_insert("location", frame=90)
```

레이어 분리(사진 한 장 → 깊이별 PNG)는 AI 아웃페인팅/뎁스맵 도구가 필요해서 **이미지 쪽 작업(코덱스 담당)과 협업이 필요**하다 — 여기서는 "받은 레이어를 배치하는 블렌더 쪽"만 정리했다.

큐브 회전 전환(장면 전환을 정육면체가 회전하며 넘어가는 것처럼)은 **조사하지 않았다** — 필요하면 다음 세션.
