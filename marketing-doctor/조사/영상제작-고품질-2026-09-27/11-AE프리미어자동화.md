# 11. After Effects · Premiere Pro 자동화 조사 (2026-09-28)

> 목적: 설계자가 "AE·Premiere 를 지금 공정(Blender+ffmpeg)에 추가할지" 판단할 재료. 설치·커밋 없음, GUI 클릭 불가 전제(Bash/PowerShell/Python 만).
> 등급: A=공식 문서/공식 스크립팅 가이드, B=Adobe 공식 포럼 답변, C=강의·블로그·커뮤니티(미검증 가능성)

### 1-1. 기본 내장만으로 만들 수 있는 「고급 연출」 목록
- 빛 스치기: **CC Light Sweep** (표면 위 빛 띠, 텍스트·로고 하이라이트)
- 빛샘·렌즈 플레어: **Lens Flare**(기본 내장, 55mm/105mm/카메라 렌즈 3종 프리셋)
- 글자 키네틱: 텍스트 레이어 **애니메이터**(Range Selector + Position/Opacity/Scale) — AE 코어 기능, 플러그인 아님
- 필름 그레인: **Add Grain**(기본 내장, CC 아님 Adobe 자체 필터)
- 파티클(단순 불꽃·먼지·빛입자): **CC Particle World**(기본 내장, 3D 파티클 시스템이나 Trapcode Particular 대비 컨트롤 단순)
- 안개·구름·유기적 흔들림: **Fractal Noise**, **Turbulent Displace**(둘 다 기본 내장)
- 3D 카메라·레이어 이동(패럴랙스): AE 코어의 3D 레이어 스위치 + Camera 레이어(플러그인 아님)
- 타일 반복·유리 왜곡류: **Motion Tile**(기본 내장)
- 아웃포커스·심도: **Camera Lens Blur**(기본 내장, iris 모양·회절까지 조절)

이 9개는 전부 **AE 기본 설치에 포함**되며 유료 플러그인이 아니다(Adobe 공식 Cycore/기본 효과 목록 확인, A등급).

## 3. 설치 — CC 앱 없이 명령줄 설치 가능한가

## 5. 우리 공정(Blender+ffmpeg)에 넣을 가치 — 판단 재료

**AE 가 지금 공정보다 나을 수 있는 지점**
- 2D 텍스트 애니메이션(글자 키네틱)은 Blender 텍스트 오브젝트보다 AE 텍스트 애니메이터가 훨씬 빠르고 세밀함(레이어 기반, 프리셋 존재)
- 빛 스치기·렌즈 플레어·필름 그레인 같은 "2D 합성 레이어"는 AE 가 전용 도구라 손이 덜 감(Blender 컴포지팅 노드로도 되지만 노드 짜는 시간이 더 듦)
- 알파 채널 출력(PNG 시퀀스·ProRes 4444)으로 AE 산출물을 Blender·ffmpeg 위에 얹는 합성 파이프라인은 이론상 가능(문서 확인, 단 템플릿을 미리 사람이 만들어야 함)

**지금 공정으로 충분해 보이는 지점**
- 3D 카메라 무빙·조경·실내 렌더는 이미 Blender Cycles 가 담당 중이고 AE 는 3D 렌더 엔진이 아님(패럴랙스 수준의 얕은 3D만 지원)
- 색보정(Lumetri)·워크폴더 인코딩은 지금 ffmpeg 로 이미 처리 가능한 수준이라 이득이 불확실(자동화 API 문서도 미확인 상태)
- **완전 무인(headless) 자동화가 확인되지 않는다.** aerender 는 "기존 .aep 렌더"만 완전 명령줄이고, 매 편마다 다른 텍스트·소재를 스크립트로 새로 짜 넣는 "완전 무인 생성"은 AE 를 잠깐이라도 GUI 상태로 띄워야 할 가능성이 높음(에이전트가 클릭은 못 해도, 창이 뜨는 것 자체는 문제 없을 수 있음 — 이 부분은 실제로 한 번 돌려봐야 확정됨, 미확인)

## 확인됨 / 미확인 / 운영자확인필요

확인됨 :
- aerender.exe 로 기존 .aep 파일을 완전 명령줄로 렌더링 가능(옵션: -project, -comp, -RStemplate, -OMtemplate, -output)
- CC Light Sweep · CC Particle World · Lens Flare · Fractal Noise · Turbulent Displace · Motion Tile · Camera Lens Blur · Add Grain · 텍스트 애니메이터는 전부 AE 기본 내장(유료 플러그인 아님)
- ExtendScript(JSX)로 컴포지션·레이어·효과·키프레임 조작 가능(docsforadobe.dev 공식 스크립팅 가이드)
- 출력모듈은 **기존 템플릿 적용**만 스크립트로 가능, 새 포맷 자체를 스크립트로 만드는 것은 불가(사람이 AE 안에서 먼저 템플릿을 만들어 둬야 함)
- Premiere ExtendScript(CEP)는 2026년 9월까지만 공식 지원, 이후 UXP 전환이 Adobe 방침
- AME 워치폴더 자동 인코딩은 가능하나 2025~2026 버전에 소스 파일 자동 이동 버그 보고 있음
- CC 앱 없는 완전 명령줄/무인 설치는 일반 구독으로는 안 됨(엔터프라이즈 CLP만 가능)

미확인 :
- `AfterFX.exe -r script.jsx`가 지금 우리 환경(Windows, AE 미설치 상태)에서 GUI 창을 얼마나 띄우는지, 그 창이 에이전트 작업(Bash 트리거)에 실제로 문제가 되는지 — 실기 테스트 필요
- Premiere UXP/ExtendScript로 Lumetri 색보정·MOGRT 값을 실제로 스크립트에서 바꾸는 공식 API 문서 원문
